# 제출 코드 — 2026 인하 AI 챌린지

첫 프레임 1장 + 16스텝 액션 궤적 → 16프레임 영상. **GPU 1장에서 백본부터 제출 CSV까지 통째로 돕니다.**

| | Public | Private |
|---|---:|---:|
| 정적 기준선 (첫 프레임 16회 반복) | 0.3019 | — |
| **이 코드의 산출물** (`submission-bg.csv`) | **0.1810** | **0.2162** |
| 배경 고정 후처리 없이 (`submission-raw.csv`) | 0.2198 | — |

**최종 순위에 쓰인 제출물은 `sub_b10-10800-cfg2-bg.csv`(Private 0.2162)이며, 이 코드가 그것을
만드는 경로입니다** — 학습 누적 10,800스텝 · 액션 CFG 2.0 · 배경 고정 q0.90.

## 1. 돌리는 법

```bash
export FT_ROOT=$HOME/ft          # 빈 폴더여도 됩니다 — 필요한 것을 알아서 받습니다
export KIT_ROOT=$FT_ROOT/kit     # 생략하면 $FT_ROOT/kit
python main.py all               # 준비 + 학습 35시간 45분 + 추론 60분
```

**`FT_ROOT` 는 빈 폴더로 시작해도 됩니다.** 없으면 아래를 알아서 받아 배치합니다.
- **백본** 9.7GB — 공개 모델 `Doubiiu/DynamiCrafter_512` 의 `model.ckpt`
- **대회 데이터와 킷** 8.6GB — 데이콘 배포 `open.zip`
- **Δ 통계** — 학습 데이터에서 1분 남짓 걸려 생성

준비만 먼저 해두려면 `python main.py prepare` 입니다. 디스크는 약 30GB 필요합니다
(백본 9.7 + 꾸러미 8.6 + 체크포인트).

학습과 추론을 따로 돌리려면:

```bash
python main.py train                        # 백본 → 누적 10,800스텝
python main.py infer                        # 마지막 체크포인트로 216문제 생성 → CSV
python main.py infer --ckpt 경로/가중치.ckpt  # 특정 체크포인트로
python main.py infer --limit 2               # 두 문제만 — 배선 확인 (3분)
```

`scripts/*.sh` 에 같은 일을 하는 셸 판이 있습니다. **`main.py` 와 셸 스크립트는 완전히 같은
명령을 같은 순서로 부릅니다** — 편한 쪽을 쓰시면 됩니다.

## 3. 방법 — 무엇이 점수를 만들었나

효과가 확인된 순서대로입니다. 괄호는 그 항목 하나를 넣었을 때의 점수 변화입니다.

**① 백본을 실제로 쓴다 (−0.21).** 대회 기본 설정은 제공된 `backbone.ckpt` 안의 1.44B UNet 을
쓰지 않고 32채널 11M 모델을 맨바닥부터 학습하도록 돼 있습니다. UNet 구조값을 백본 실측치에
맞추고(`model_channels 320` · `channel_mult [1,2,4,4]` · `num_head_channels 64` ·
`attention_resolutions [4,2,1]` · `use_scale_shift_norm False`) `only_reload_modules` 에 `model` 을
넣으면 1,468/1,517(96.8%)이 실립니다.

**② 액션을 cross-attention 으로 넣는다.** 액션 12차원(절대 6축 + 차분 6축)을 두 갈래로 만듭니다
(`src/model.py: ActionCtxUNet`).
- **프레임별 토큰 16개** — 이미지 토큰 자리에 더합니다. 프레임 t 에는 t 시점의 액션이 들어갑니다.
- **궤적 요약 토큰 32개** — 빈 텍스트 슬롯 77칸 중 뒤 32칸에 더합니다. 16프레임 전체가 공유합니다.

**③ 학습 스텝을 고르는 축이 있고, 그 곡선은 단봉이 아니다.** 누적 10,800스텝이 우리가 찾은
최적입니다. 이 값을 고르는 과정에서 두 번 크게 틀렸으므로 그대로 적어둡니다.

- **처음에는 9,000 이 정점이라고 판단했습니다.** CFG 1.0 으로 스텝 축을 훑었을 때 9,000 이 가장
  좋았고, 10,200 은 0.2794 로 "최악"이라 그 구간을 통째로 버렸습니다.
- **그런데 최종 레시피(CFG 2.0 + 배경 고정)로 다시 재니 그 버린 구간이 가장 좋았습니다.**
  10,800 = 0.1810 으로, 9,000(0.2091)을 0.028 앞섭니다. **CFG 이득의 크기가 체크포인트마다
  극단적으로 다르기 때문에, CFG 1.0 점수로 스텝을 고른 방식 자체가 틀렸습니다.**
- **더 긴 학습이 나쁘다는 것도 틀렸습니다.** 누적 20,400 · 21,600 · 22,800 이 각각 0.1994 ·
  0.1894 · 0.1981 로, 이 구간 전체가 9,000 보다 좋습니다.

최종 레시피 기준으로 실측한 스텝 축입니다(전부 CFG 2.0 + 배경 고정 · Public):

| 누적 | 9,000 | 10,200 | **10,800** | 12,600 | 13,200 | 15,600 | 16,800 | 20,400 | 21,600 | 22,800 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 점수 | 0.2091 | 0.2292 | **0.1810** | 0.2056 | 0.2320 | 0.2070 | 0.2192 | 0.1994 | 0.1894 | 0.1981 |

**10,800 은 600스텝 옆(10,200 = 0.2292)과 0.048 벌어진 뾰족한 지점입니다.** 대회 종료 후
Private 점수를 확인해보니 이 격차는 표본 운이 아니라 실제 실력 차였습니다(아래 6-2절).

**④ 액션 CFG 2.0 (−0.022).** CFG(classifier-free guidance)는 조건을 준 예측과 안 준 예측의 차이를
증폭하는 추론 기법입니다. **네 값을 다 재서 고른 값입니다** — 누적 9,000 · 배경 고정을 함께 쓴 조건:

| CFG | 1.0 | **2.0** | 2.5 | 3.0 |
|---|---:|---:|---:|---:|
| 점수 | 0.2306 | **0.2091** | 0.2110 | 0.2154 |

2.0 과 2.5 의 차이(+0.0019)는 잡음 범위라 곡선이 그 사이에서 평평합니다. 3.0 부터 과증폭입니다.

**주의 — 이 표는 누적 9,000 에서 잰 것이고, 이득의 크기는 체크포인트마다 크게 다릅니다.**
9,000 에서 −0.022 였던 CFG 이득이 10,800 에서는 훨씬 큽니다. 축 하나를 한 지점에서 재고
전 구간에 적용한 것이 우리가 저지른 가장 비싼 실수였습니다(③ 참조). **최적값 2.0 자체는
두 구간에서 모두 확인했습니다.**

**⑤ 배경 고정 후처리 (누적 10,800 에서 −0.039).** 생성 영상에서 **시간에 따라 변한 자리(=로봇 팔)만 남기고**
나머지 픽셀은 첫 프레임으로 되돌립니다(`src/bgfreeze.py`). 학습도 GPU 도 필요 없고 216개에 90초입니다.
확산 모델이 배경에 남기는 미세한 흔들림이 DINO·Video 항목에서 그대로 감점되기 때문에 효과가 큽니다.

강도(`--quantile`)도 **같은 영상에 값만 바꿔 재서 골랐습니다**:

| quantile | 0.80 | **0.90 (기본값)** | 0.95 |
|---|---:|---:|---:|
| 생성분이 남는 면적 | 55% | **34%** | 27% |
| 점수 | 0.2152 | **0.2091** | 0.2208 |

양쪽이 다 나쁜 볼록 곡선이라 0.90 이 최적입니다. **비대칭이 하나 있습니다** — 더 얼리는 쪽(+0.0117)이
덜 얼리는 쪽(+0.0061)보다 두 배 나쁩니다. 즉 **팔을 조금 지워버리는 실수가 배경을 조금 남기는
실수보다 비쌉니다.** 마스크가 애매하면 넓게 잡는 편이 안전합니다.

이 표도 누적 9,000 에서 잰 것입니다. **이득의 크기는 모델마다 −0.021 ~ −0.057 로 두 배 넘게
흔들리지만**(9,000 −0.021 · 10,800 −0.039), 최적 강도가 0.90 이라는 결론은 바뀌지 않았습니다.

**학습이 4단계로 쪼개져 있는 이유**는 실제로 그렇게 학습했기 때문입니다. 단계를 넘을 때
UNet 가중치만 물려받고 **옵티마이저 상태는 새로 시작하며 학습률 워밍업도 다시 돕니다.**
10,800스텝을 한 번에 도는 것과 결과가 같지 않으므로, 재현하려면 이 순서 그대로여야 합니다.

| 단계 | 스텝 | 바뀌는 것 |
|---|---:|---|
| stage1 | 300 | 인코더 동결 · 액션 조건 **없음** — 백본을 데이터에 적응만 시킵니다 |
| stage2 | 2,100 | 인코더 해제 + 8비트 AdamW + **액션 cross-attention 투입** |
| stage3 | 1,800 | stage2 와 설정 동일 |
| stage4 | 6,600 | stage2 와 설정 동일 → 누적 **10,800** |

## 3-1. 해보고 버린 것들

여기 없는 것은 안 해본 게 아니라 **재보고 나쁘길래 뺀 것**입니다. 괄호는 최종 레시피 대비 점수 변화입니다.

| 버린 것 | 결과 |
|---|---|
| **움직임 가중 손실** (`motion_weight` 2.0 / 4.0) | 정점 위치를 앞당기지만(9,000 → 7,800 → 5,400) **정점의 깊이는 나아지지 않는다.** 2.0 은 동률(−0.0007), 4.0 은 손해(+0.009). 게다가 2.0 은 CFG 에 **반대로 반응해서**(+0.016) 최종 레시피와 궁합이 나쁘다 |
| **`guidance_rescale` 0.7** | +0.0135 — 증폭 후 통계를 눌러 유용한 액션 증폭까지 깎는다 |
| **순수 액션 CFG** (이미지 조건은 두고 액션만 뺀 무조건부) | +0.0018, 잡음 범위. 킷 기본 무조건부가 검은 이미지를 쓰는 것이 실질적 문제가 아니었다 |
| **액션 한 칸 밀기** (`action_shift` 1) | +0.0138 — **현재 정렬(same-index)이 맞다는 확인** |
| **모델 수프** (`reference/soup.py`) | 세 번 써서 세 번 다르게 나왔다 — 9,000×9,600 은 **두 부모를 다 이겼고**(0.2042), 10,200×10,800 은 **정확히 산술평균**이었으며(0.2048, 예측 0.2051), 10,800×12,600 은 보간보다는 좋지만 최고 부모에 미달했다(0.1864 vs 0.1810). 갈래를 건너뛴 수프는 +0.015 로 확실히 나쁘다. **남는 결론: 평균보다 나은 지점은 주지만 최고 부모를 이긴다는 보장이 없다** |
| ~~**더 긴 학습**~~ | **이 판단은 철회한다.** CFG 1.0 곡선에서만 그렇게 보였을 뿐이고, 최종 레시피로 재면 20,400~22,800 구간이 9,000 보다 좋다(위 ③ 참조). 다만 최적은 여전히 10,800 이다 |
| **DDIM 50 → 15** | 초기 실험에서 더 선명한 판이 오히려 나빴다 |

## 6-3. 재학습 재현 검증 (2026-08-28)

운영진 요청에 따라 **같은 코드·설정·시드로 백본부터 전 구간을 다시 학습**하고 점수를 대조했습니다.

| | Public | Private |
|---|---:|---:|
| 원본 (2026-08-19 학습) | 0.1810 | 0.2162 |
| **재학습본 (2026-08-26~28)** | 0.1886 | **0.2239** |
| 차이 | +0.00759 | **+0.00772** |

**두 지표가 거의 같은 폭으로 움직였습니다** — 차이의 차가 0.00013(상대차 1.7%)입니다. Public 과
Private 는 서로 다른 표본인데도 같은 크기로 벌어졌으므로, 이 격차는 표본 잡음이 아니라 **두 모델의
실제 성능 차**로 보는 것이 맞습니다. 파이프라인이 제대로 재현됐다는 뜻이기도 합니다.

크기 감각을 위해: 같은 학습 궤적에서 600스텝 떨어진 이웃 체크포인트끼리는 0.048 차이가 났습니다.
**재학습으로 생긴 차이(0.0077)는 그 1/6 이고, 원본 대비 3.6% 입니다.**

차이가 남는 이유는 둘입니다.

1. **학습 비결정성** — 시드(20230211)를 고정해도 데이터로더 순서와 cuDNN 커널 선택까지는 고정되지
   않습니다. `torch.use_deterministic_algorithms` 는 쓰지 않았습니다(속도 저하가 커서 4일 제한에 걸립니다).
2. **선택 효과** — 원본의 누적 10,800 은 여러 체크포인트를 모두 재보고 **가장 좋은 것을 고른** 값이고,
   재학습본은 고르지 않은 한 번의 뽑기입니다. 평균 쪽으로 조금 물러나는 것이 정상입니다.

## 8. 알아둘 점

- **`use_ema: False` 입니다.** 켜면 EMA 사본이 5.4GB 를 더 먹고, 백본에 `model_ema.*` 가 없어
  학습 0스텝 상태에서는 전 프레임이 노이즈로 나옵니다.
- **어텐션을 torch SDPA 로 교체합니다**(`src/model.py`). 킷 기본 구현으로는 32GB GPU 에 안 들어갑니다.
  96GB 환경에서는 없어도 되지만, 결과를 바꾸지 않으므로 그대로 둡니다.
- **`save_top_k: -1`, monitor 없음.** 검증 손실이 낮을수록 점수가 좋아지지 않았습니다(오히려 반대인
  구간이 있었습니다). 그래서 손실로 체크포인트를 고르지 않고 전부 남긴 뒤 제출 점수로 골랐습니다.
- **`submission-raw.csv` 도 같이 나옵니다.** 영상 후처리가 규정상 불가하다는 판단이 있을 경우를
  대비한 배경 고정 없는 판입니다(0.2299).
