# reference — 실제로 굴린 것들의 원본

`submission/` 본체는 백본에서 제출 CSV 까지 한 벌로 정리한 **재현 코드**다.
여기 있는 것은 그 정리 이전에 **실제로 서버에서 돌아갔던 파일들**이다.
대회가 끝나고 서버·pod 을 정리하면서, 장부([results/submissions.csv](../../results/submissions.csv))의
숫자와 짝이 맞는 원본만 남겼다.

| 파일 | 무엇 |
|---|---|
| `soup.py` | 모델 수프 — 같은 궤적 위 두 체크포인트의 가중치 평균. **본체 `src/` 에 없는 유일한 기법** |
| `base-10-cfg2.0.yaml` | 팀 최고점 **0.1810**(누적 10,800 · CFG 2.0 · 배경 고정)을 만든 추론 설정 |
| `run_one.sh` | 생성 → 배경 고정 → CSV 를 한 줄로 묶은 오케스트레이션. 대부분의 측정이 이걸로 나왔다 |
| `v100_night.sh` | 마지막 밤(8/19~20) V100 큐 6판. **무엇을 왜 그 순서로 돌렸는지가 주석에 있다** |
| `overnight.sh` | pod 쪽 야간 작업 — 누적 16,800 → 22,800 학습 후 다섯 지점 생성 |
| `b10y_cfg2.sh` | 그 다섯 지점을 최종 레시피(CFG 2.0)로 다시 뽑은 것 |
| `selfstop.sh` | pod 이 스스로 CSV 를 HF 에 올리고 반납하는 감시 |

## soup.py — 세 번 써서 세 번 다르게 나왔다

| 재료 | 결과 | 최고 부모 대비 |
|---|---|---|
| 9,000 × 9,600 | 0.2042 | **두 부모를 다 이김** |
| 10,200 × 10,800 | 0.2048 | **정확히 산술평균**(예측 0.2051) |
| 10,800 × 12,600 | 0.1864 | 보간(0.1933)보다 좋지만 **최고 부모(0.1810) 미달** |

가중치 평균은 **두 부모의 평균보다 나은 지점을 준다.** 다만 **최고 부모를 이긴다는 보장은 없다** —
처음에 "인접하기만 하면 이득"으로 읽었다가 두 번 고쳐 쓴 결론이다.

## selfstop.sh — 감시는 원격에 두어야 한다

8/20 새벽, 맥에서 돌던 감시가 01:22 에 배터리로 잠들었고 pod 작업은 04:30 에 끝났다.
감시를 pod 안으로 옮겨두지 않았다면 CSV 다섯 장이 정지된 볼륨에 갇힌 채
잔액만 태웠을 것이다. **맥에 의존하는 감시는 맥이 죽으면 같이 죽는다.**

## 잃은 것 — b10y 계보 설정

**`pod-b10x.yaml` · `pod-b10y.yaml` · `infer-b10y.yaml` 은 없다.** pod 볼륨에만 있었고
8/21 새벽 잔액 소진과 함께 pod 이 자동 삭제되면서 사라졌다. 체크포인트도 같이 갔다.

즉 **누적 15,600 ~ 22,800 구간(21,600 = 0.1894 포함)은 지금 이 저장소만으로 재현되지 않는다.**
다만 `overnight.sh` 에 파생 방법이 남아 있어 재구성은 가능하다 — `base-10` 설정에서
`name` · `max_steps` · `resume_unet` 세 줄만 바꾼 것이다.

이 구간이 왜 중요했는지는 장부에 있다: **다섯 점(18,000·19,200·20,400·21,600·22,800)이
0.1894~0.2050 안에 모인 넓은 골짜기**로, 초반 구간에서 유일하게 좋았던 10,800(0.1810)이
양옆 이웃과 0.025~0.048 벌어진 고립 첨점이었던 것과 대조된다.
