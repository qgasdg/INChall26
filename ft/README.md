# ft — baseline 파인튜닝, 한 칸씩

담당: 윤택. 태양님의 DynamiCrafter 결합(step0 0.3031)을 **출발선으로 삼고**,
설정을 하나씩만 바꿔가며 점수가 어디서 움직이는지 찾는다.

## 왜 이 방향인가

제출 이력([docs/dacon_submission.md](../docs/dacon_submission.md))이 이상하다.

```
0스텝    0.3031  ← 최고
500스텝  0.3270
1250스텝 0.3467
1750스텝 0.3292
```

**학습할수록 나빠진다.** 그런데 리더보드 1위는 0.171이고 10위도 0.248이다.
정적(0.3019)을 크게 이기는 팀이 열 팀 넘는다 — 즉 **움직임이 손해인 판이 아니라
우리 학습이 잘못 굴러가고 있는 것**이다. 원인이 레시피 어딘가에 있고,
아직 아무도 안 건드린 손잡이가 남아 있다는 가정에서 출발한다.

## 원칙

1. **결과는 [results/submissions.csv](../results/submissions.csv) 장부에 append**하고,
   아래 실험 표에도 한 줄 남긴다.
2. 데이콘에 결과를 제출할 때마다 커밋/푸시로 코드 기록을 남겨 놓는다.

## 백본을 제대로 싣기까지 고친 것 (2026-08-07)

대회 config 그대로는 **1,107개 텐서 중 1개**만 실린다. 아래를 다 맞춰야 1.4B 가 온전히 올라간다.
전부 `backbone.ckpt`(= HF `Doubiiu/DynamiCrafter_512` 의 `model.ckpt`) 실측 shape 으로 확정했다
(`probe_backbone.py`, `probe_load.py`).

| 항목 | 대회 원본 | 실측 | 안 고치면 |
|---|---|---|---|
| `model_channels` | 32 | **320** | 구조 자체가 다름 |
| `channel_mult` | [1,2,3] | **[1,2,4,4]** | 〃 |
| `num_head_channels` | 16 | **64** | 〃 |
| `attention_resolutions` | [4,2] | **[4,2,1]** | 〃 |
| `use_scale_shift_norm` | True | **False** | ResBlock `emb_layers` 가 정확히 2배 어긋나 적재 자체가 예외로 죽는다 |
| `add_act_time_emb` | 없음(=False) | **True** | `time_embed.2` 가 shape 불일치로 랜덤 초기화 |
| `only_reload_modules` | UNet 제외 | **UNet 포함** | 백본이 아예 안 실림 |

**★`use_ema: True` — 0스텝 생성에서 치명적.**
`LitEma` 는 모델을 만드는 시점의 가중치를 복사해두는데 그 시점은 **사전학습을 싣기 전**이고,
`backbone.ckpt` 에는 `model_ema.*` 가 없어 갱신되지도 않는다. 그래서 `ema_scope()` 안에서
생성하면 **랜덤 가중치로 생성한다.** 실제로 전 프레임이 컬러 노이즈로 나왔고, 끄자 정상 영상이 나왔다.
학습된 체크포인트에는 EMA 가 저장되므로 학습 후 추론에서는 드러나지 않는다 — 0스텝에서만 터진다.

`action_embed` 를 0으로 초기화해도 노이즈는 그대로였다 → **액션 임베딩은 원인이 아니었다.**

## 액션 전용 학습 (2026-08-08)

**질문.** 제출 이력은 예외 없이 "학습하면 나빠진다"인데, 그것이 ① 파인튜닝이 사전학습 prior 를
망가뜨려서인지 ② 액션 경로 자체가 무력해서인지 분리된 적이 없다. 백본을 물리적으로 동결하고
zero-init 인 `action_embed`(1.66M / 1440.51M = 0.115%)만 학습하면 ①이 원천 차단된다.

두 판을 각각 600스텝(유효 배치 16) 돌렸다. 차이는 손실 하나뿐이다.

| | 손실 | 시간 |
|---|---|---|
| ft-10 | 기본 (v-예측 MSE) | 2.1시간 |
| ft-11 | 기본 + **액션 대조 항** | 3.7시간 |

**액션 대조 항.** 같은 `x_noisy`·같은 `t`·같은 노이즈에서 정답 액션과 **시간축을 섞은** 액션으로
두 번 예측하고 `relu(margin − gap)` 를 더한다. 여기서

```
gap = (mse_shuffled − mse_true) / mse_shuffled
```

화질을 올려서는 이 항을 못 줄인다 — 두 예측이 같이 좋아지면 차이가 그대로다. 오직 출력이
액션에 **올바르게 의존해야만** 줄어든다. 배경은 두 예측에서 상쇄되므로 "배경이 기울기를
독식한다"는 문제도 자동으로 빠진다.

### 결과 — 대조 손실이 있어야 액션이 붙는다

홀드아웃(학습에 안 쓴 에피소드) 24배치, 같은 배치·`t`·노이즈로 짝지어 측정:

| 체크포인트 | 평균 gap | 표준오차 | >0 비율 |
|---|---:|---:|---:|
| zero-init (학습 전) | +0.00000 | 0.00000 | 0.0% |
| ft-10 100 | +0.00054 | 0.00109 | 45.8% |
| ft-10 300 | −0.00117 | 0.00213 | 58.3% |
| ft-10 600 | +0.00177 | 0.00084 | 54.2% |
| ft-11 100 | +0.00317 | 0.00231 | 58.3% |
| ft-11 300 | +0.00796 | 0.00450 | 54.2% |
| **ft-11 500** | **+0.02524** | 0.00840 | 62.5% |

**기본 손실(ft-10)로는 600스텝을 밟아도 액션이 전혀 안 붙는다** — 전부 표준오차 1~2배 안의 잡음이고
추세도 없다. 대조 손실(ft-11)은 단조 증가해 500스텝에 3σ로 유의하다.

학습 중 로그도 같은 그림이다(마이크로배치 19,200개를 10구간으로):

```
     0~ 1920   gap +0.00001   >0 50.6%   ← zero-init 이라 정확히 우연
  5760~ 7680   gap +0.01693   >0 67.4%
 11520~13440   gap +0.03449   >0 77.0%
 17280~19200   gap +0.05763   >0 84.0%
전반부 +0.01059 → 후반부 +0.04179 (차이 +0.0312, 표준오차 0.00077)
```

**함의.** "액션 조건이 작동하지 않는다"의 원인 하나가 **손실이 액션을 안 물어봤다는 것**이다.
motion-weighted(v2)·anchor(v3) 는 "어디가 변하나"만 다뤘지 "액션과 그 변화가 맞물리나"는 안 물었다.

**아직 증명 안 된 것.** gap 은 학습 목적함수 위의 개선이다. ① 생성 영상이 실제로 액션을 따라가는지
② 리더보드 점수가 좋아지는지는 별개다. ⑥번 발견(선명할수록 나쁨)을 생각하면 낙관할 수 없다.

### 제출 결과 — 액션이 붙었고, 점수는 나빠졌다

ft-11 500스텝 학습본으로 216개를 생성해 제출했다(ft-12). 샘플링 설정은 ft-05 와 **완전히 동일**하므로
차이는 학습된 `action_embed` 하나뿐이다.

```
ft-05 (학습 전, zero-init)   0.3948
ft-12 (ft-11 500스텝 학습본)  0.4888     +0.0940 악화
```

**이 결과가 가르는 것.** 백본은 비트 단위로 동결이 검증됐고(표본 40개가 backbone 과 완전 일치)
바뀐 것은 1.66M(0.115%)뿐이다. 그런데도 점수가 크게 나빠졌다.

- **①「파인튜닝이 사전학습 prior 를 망가뜨린다」 → 기각.** 망가뜨릴 여지가 없었다.
- **②「액션 경로를 통해 들어간 영향 자체가 손해다」 → 확정.**

그리고 홀드아웃 gap 이 +0.02524(3σ)이므로 **액션이 안 먹혀서가 아니다. 먹힌 결과가 틀린 것이다.**
지금 구조에서 액션이 낼 수 있는 것은 프레임당 1280차원 벡터 하나 →
ResBlock `emb_layers`(동결) → **공간 방향으로 브로드캐스트되는 채널별 상수**다.
"얼마나 움직여라"는 말할 수 있어도 **"어디로"는 표현할 자리가 없다.**
그래서 학습이 만들어낸 것은 "더 움직여라"이고, 방향이 틀리면 그건 순손해다 — ⑥번과 같은 이야기다.


## 잔차 모델 (ft-20) — 바닥은 깔렸고, 오프셋이 값을 치렀다

출력을 `z_정적 + Δ` 로 바꾸고 출력 conv 를 zero-init 해서 **0스텝 출력이 첫 프레임 16회 반복과
비트 단위로 같게** 만들었다(실측 프레임 간 차이 0.000000). 600스텝 학습 후 제출 결과:

```
정적            0.3019   ← 여전히 최고
ft-20 잔차      0.3403   ← 우리 생성물 중 최고 (직전 최고 0.3729 대비 -0.0326)
ft-01           0.3729
ft-12           0.4888
```

**설계 의도의 절반은 통했다.** 뭉개짐·환각이 사라졌고, 0.49 대에서 0.34 로 내려왔다.

**나머지 절반은 실패했다 — 정적에 0.0384 미달한다.** 생성물을 재보면 원인이 명확하다.

| | 값 (0~255) |
|---|---:|
| 정적 대비 **전역 오프셋** | 3.2 |
| **프레임 간 변화**(진짜 움직임) | 0.8 |

`Δ` 의 대부분이 **시간에 대해 상수인 전역 보정**이다. 영상 전체를 1.3% 밝게 밀었을 뿐 팔은 안 움직였다.

**왜 그렇게 학습됐나.** 목표 `Δ = z_정답 − z_정적` 의 **시간 평균이 0 이 아니다**(조명·모션블러·
팔의 평균 위치). 시간 상수 값 하나만 맞혀도 MSE 가 10% 준다. 모델은 가장 쉬운 길을 갔다.
**`rel_to_static` 이 1.0 → 0.90 으로 떨어진 것을 "학습이 이득을 만드는 중"으로 읽은 것은 착시였다.**

**그리고 값비싼 교훈 하나.** 눈에 잘 안 보이는 **1.3% 전역 밝기 변화가 0.038 을 깎는다.**
지표가 외형 충실도에 그만큼 민감하다는 첫 정량 관측이다.

**처방(ft-21).** 손실을 **시간 차분**에 건다 — `MSE(Δ의 시간차분, 목표의 시간차분)`.
상수 성분은 차분에서 소거되므로 **전역 오프셋으로는 손실을 1도 못 줄인다.**
진단값으로 `delta_const_rms`(오프셋)와 `delta_vary_rms`(진짜 움직임)를 따로 찍어 착시를 막는다.

**다음 수는 '학습을 더/덜'이 아니라 '경로를 바꾸는 것'이다.** 액션이 공간 위치를 직접 지목할 수 있는
주입 경로(cross-attention 등)가 아니면 이 천장을 못 넘는다.



### 운영 메모

- 체크포인트는 5.4GB 인데 실제로 바뀐 건 1.66M(6.6MB)뿐이다. `extract_action_ckpt.py` 로
  액션 텐서만 뽑고 나머지는 지운다. **뽑기 전에 동결 텐서 40개를 backbone 과 대조**해
  동결이 실제로 지켜졌는지 검증한다 (11개 전부 통과).
- ft-11 은 600스텝을 다 채우고 **마지막 체크포인트 저장에서 디스크가 차 죽었다.** 500스텝판이 최종본이다.

## 실행


## 남은 약점

제출 점수 말고 품질을 잴 수단이 없다. 하루 10회로는 변수 열 개가 상한이고,
같은 설정을 두 번 내볼 여유가 없어 **노이즈인지 실제 개선인지 구분이 안 된다.**
A~C가 정리되면 자체 IDM(연속 두 프레임에서 관절 움직임을 역추정하는 모델) 학습으로
로컬 지표를 붙이는 것이 다음 순서다.
