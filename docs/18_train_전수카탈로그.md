# train 데이터 전수 카탈로그 (48h 계획 Phase 1)

> 실행: Y측 서버 클로드 / 인하 V100 서버 / 2026-07-20. 산출물 = [results/train_catalog.csv](../results/train_catalog.csv) (데이터셋 1행), [train_short_episodes.csv](../results/train_short_episodes.csv), [train_catalog_meta.json](../results/train_catalog_meta.json). 생성 스크립트 = [scripts/eda03_train_catalog.py](../scripts/eda03_train_catalog.py) (전수 재현 60초, 32 프로세스 병렬).

**용어**: EDA(Exploratory Data Analysis, 데이터 탐색 분석) · fps(frames per second, 초당 프레임 수) · 코덱(codec, 영상 압축 방식) · 에피소드(로봇이 과제를 1회 수행한 녹화 1건) · 액션 6차원(로봇 팔 관절 6개의 목표 각도).

## 결론 먼저

1. **기존 EDA 수치는 전수 실측으로 전부 확인됨** — 128 데이터셋 / 11,132 에피소드 / 1,025,666 프레임 / <16프레임 에피소드 34개. ([05_EDA검증](05_EDA검증.md) 재확인, 불일치 0)
2. **데이터가 균질하지 않다** — 학습 파이프라인이 반드시 흡수해야 할 이질성 4종을 전수 목록화했다(§2). 해상도 3종·코덱 2종·fps 2종·카메라 키 2종.
3. **`wrist_roll`(손목 회전축)이 가장 불안정한 차원** — 데이터셋 간 평균 편차가 47.78로 2위(`elbow_flex` 25.79)의 약 2배. 기존에 발견된 "eval의 wrist_roll이 train 대비 +1.5σ 시프트"([05](05_EDA검증.md) ③)와 같은 뿌리로 보이며, **정규화 전략의 최우선 대상**이다(§4).
4. **조사② 종결** — <16프레임 에피소드 34개(전체의 0.305%) 전수 목록 확보. 그중 **27개가 길이 1프레임**인 사실상 빈 녹화라, 필터는 단순 길이 컷으로 충분하다.
5. **조사④ 정정 + 종결** — docs/05가 카메라 키 예외로 지목한 `liyitenga/so100_bi_giveme5`는 **train 데이터에 존재하지 않는다**. 실제 예외는 `triton7777/so100_dataset_mix`이고, 육안 확인 결과 뷰는 평범해 **학습 제외 사유 없음**(§3).

## 2. 이질성 4종 (파이프라인이 흡수해야 할 것)

### ① 해상도 3종
| 해상도 | 데이터셋 수 | 해당 데이터셋 |
|---|---|---|
| 640×480 | 123 | (기본) |
| 1280×720 | 2 | `mikechambers/block_cup_14`, `pranavsaroha/so100_carrot_5` |
| 1920×1080 | 3 | `pranavsaroha/so100_legos4`, `so100_onelego2`, `so100_onelego3` |

킷(제출 킷) 규격이 320×512 레터박스(letterbox, 비율 유지하며 여백 채우기)라 전처리에서 흡수되지만, **원본 종횡비가 4:3(640×480)과 16:9(1280×720·1920×1080)로 갈린다** → 레터박스 여백 비율이 달라지므로 학습 시 도메인 신호로 새어 들어갈 수 있다. eval은 전량 640×480이다.

### ② 코덱 2종
av1 81개 / h264 47개. 디코딩 속도와 압축 아티팩트(artifact, 압축으로 생기는 화질 열화) 특성이 다르다. **데이터 로더 성능에 영향** — av1은 일반적으로 디코딩이 느리다.

### ③ fps 1종 예외
`dragon-95/so100_sorting` 단 1개만 **10fps**(나머지 127개는 6fps). 원본 50fps를 5로 다운샘플한 결과다(다른 데이터셋은 30fps→5). **행동 시퀀스의 시간 간격이 다르다**는 뜻이라, 16프레임 윈도우가 담는 실시간 길이가 이 데이터셋만 1.6초(다른 곳은 2.67초)다. → 학습 제외 또는 재샘플링 후보.

### ④ 카메라 키 1종 예외
`triton7777/so100_dataset_mix`만 `observation.images.s_left`(나머지 127개는 `observation.images.image`). 키 이름만 다르고 뷰는 정상(§3).

## 3. 조사④ 종결 — 카메라 키 예외

**docs/05의 지목 대상이 잘못됐다.** `liyitenga/so100_bi_giveme5`는 train 128개 어디에도 없다(디렉토리 부재). 실제 예외는 `triton7777/so100_dataset_mix` (65 에피소드 / 13,269 프레임 / 640×480 / h264 / 6fps).

첫 프레임 육안 확인 결과: 분홍 커팅 매트 위의 테이프를 내려다보는 **평범한 작업대 뷰**로, 다른 데이터셋과 성격이 다르지 않다. `s_left`는 스테레오(양안) 카메라의 좌측 채널을 뜻하는 명명으로 보이나 저장된 것은 단일 영상이다. → **학습 제외 불필요. 로더는 키 이름을 하드코딩하지 말고 info.json에서 dtype=="video"인 키를 찾아 쓰면 된다** (본 카탈로그 스크립트가 그 방식을 씀).

**부수 발견 — `Chojins` 계열(4개, 1,557 에피소드 / 130,472 프레임 = 전체 프레임의 12.7%)**: 체스 장면인데 **어안(fisheye, 광각 왜곡) 렌즈 + 상단 거울 반사**가 있어 뷰가 매우 특이하다. 규모가 커서 균등 샘플링 시 학습을 크게 끌어당긴다. eval 환경(검은 매트형·나무 책상형, [10_조사_eval도메인](10_조사_eval도메인.md))과 성격이 멀어 보이나, **제외 판정은 육안이 아니라 Phase 2 유사도 정량화로 내린다**(근거 기반 원칙).

## 4. 액션 6차원 분포 — 정규화 전략의 근거

데이터셋별 평균을 낸 뒤, 그 평균들이 데이터셋 사이에서 얼마나 흩어지는지(=설정 차이에 얼마나 민감한지) 본 값이다.

| 차원 | 전역 평균 | **데이터셋 간 편차** | 데이터셋 내 평균 std | 전체 범위 |
|---|---|---|---|---|
| shoulder_pan | 1.37 | 13.84 | 20.66 | [-122.61, 125.24] |
| shoulder_lift | 120.27 | 21.93 | 45.98 | [-15.82, 210.67] |
| elbow_flex | 109.89 | 25.79 | 40.72 | [-269.30, 190.46] |
| wrist_flex | 61.12 | 19.91 | 20.78 | [-112.85, 122.26] |
| **wrist_roll** | -16.77 | **47.78** | 22.88 | [-253.12, 243.81] |
| gripper | 11.74 | 8.11 | 14.21 | [-8.36, 119.41] |

**핵심**: `wrist_roll`은 데이터셋 간 편차(47.78)가 데이터셋 내 변동(22.88)의 **2배가 넘는** 유일한 차원이다. 즉 이 축의 값은 "로봇이 무엇을 하는가"보다 **"누가 어떻게 조립·영점조정했는가"를 더 많이 담고 있다.** 이는 eval의 wrist_roll이 +1.5σ 시프트된 이유를 설명하며(하드웨어 차이 가설과 정합), 전역 통계 하나로 z-정규화(z-score, 평균 0·표준편차 1로 맞추기)하는 현행 방식이 **이 축에서만 유독 불리**함을 뜻한다.

→ Phase 4 전략 기안에서 다룰 후보: 데이터셋별 wrist_roll 중심 정렬(per-dataset centering), 또는 이 축의 손실 가중치 조정. **단, 킷 채점기는 전역 통계로 정규화하므로 최종 산식과의 정합을 반드시 확인해야 한다** (설정값≠실효값, 룰북 §7).

## 5. 조사② 종결 — <16프레임 에피소드 34개

전체의 0.305%. **길이 분포: 1프레임 27개 / 5·8프레임 각 1개 / 13·14프레임 각 2개 / 15프레임 1개.**

압도적 다수(27/34)가 1프레임짜리 사실상 빈 녹화다. 최다 보유는 `HITHY/so100_peach4` 7개.

**필터 사양 제안 (구현은 T 영역 — [룰북](13_팀_룰북.md) §8):**
```
에피소드 길이 < 16 이면 제외.  (34개, 전체의 0.305% — 점수 영향 무시 가능, 크래시 방지가 목적)
윈도우 샘플링은 start ∈ [0, length-16] 에서만.
```
전수 목록은 [results/train_short_episodes.csv](../results/train_short_episodes.csv) (dataset, episode_index, length).
