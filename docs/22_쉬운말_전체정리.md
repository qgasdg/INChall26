## 1. 한눈에 요약 (30초)

- **무슨 대회인가.** 로봇 팔의 **시작 사진 1장 + 앞으로 할 행동 명령표**를 받아, 그 로봇이 어떻게 움직일지 **16장짜리 짧은 영상**을 만들어내는 AI를 겨루는 대회다(데이콘 2026 인하 인공지능 챌린지).
- **어떻게 채점하나.** 만든 영상을 정답 영상과 비교해 **① 장면이 닮았나(DINO, 30%) ② 움직임이 닮았나(Video, 30%) ③ 명령대로 움직였나(Action, 40%)** 를 재고 합친다. **점수는 낮을수록 좋다.** Action이 가장 중요.
- **지금 상황.** 우리 팀은 "화면이 안 움직이는 정지 영상"을 내는 단순 전략으로 점수 0.303을 받아 리더보드 **12위**. 그런데 최근 상위권이 진짜 생성 모델로 치고 올라와 **1위가 0.05665**까지 내려갔다(정지 전략의 한계선 0.303은 상위권에선 이미 깨짐).
- **우리 계획.** 지금의 작은 기본 모델(베이스라인)은 영상을 뭉개서 정지 영상보다도 못하다. 그래서 **제대로 된 영상 생성 모델(IRASim·Wan2.2)로 갈아타 학습**시키고, 그 위에 **best-of-N(여러 번 만들어 제일 좋은 것 고르기)** 같은 마무리 기법을 얹는다.
- **역할.** 팀은 두 축으로 나뉜다 — **T**(팀원 쪽: 실제 모델 학습·Kaggle·주력 모델 구현)와 **Y**(우리 쪽: 서버 운영·데이터 분석·문서·자율 실험). 정본 기록은 전부 이 저장소(repo)의 docs/에 둔다.

## 2. 용어집 (통합)

문서 전체에 나오는 축약어·전문용어를 한데 모아 쉬운 뜻을 달았다. 중복은 합쳤다.

### 2.1 대회·채점 기본
- **월드 모델 (world model)** — 로봇이 어떤 행동을 하면 화면이 어떻게 바뀔지 예측해 영상으로 그려내는 AI. 이 대회의 과제 그 자체.
- **조건부 비디오 생성** — 주어진 조건(시작 사진 + 행동 명령)에 맞는 영상을 만드는 것.
- **프레임 (frame)** — 영상을 이루는 낱장 사진 한 컷. 이 대회는 정확히 16장.
- **조건 프레임 (t=0)** — 문제로 주어진 시작 사진. 영상 0번 자리에 그대로 넣어야 하는 "공짜 정답". 실제로 새로 지어내는 미래는 나머지 15장.
- **fps (초당 프레임 수)** — 1초에 몇 장을 보여주는가. 대부분 6fps(예외로 10fps 하나). 점수 자체와는 무관.
- **행동 시퀀스 / Action (액션)** — 로봇 팔이 시간 순서로 할 동작을 적은 숫자표. 16스텝 × 6관절.
- **Score (총점)** — `0.3×DINO + 0.3×Video + 0.4×Action`. 세 항목 모두 정답과의 "거리"라 **낮을수록 좋다.**
- **DINO 성분 (30%)** — 만든 영상의 각 장면이 정답 장면과 "보기에" 얼마나 닮았나. DINOv2라는 AI가 사진을 숫자로 바꿔 비교.
- **Video 성분 (30%)** — 만든 영상의 "움직임 흐름"이 정답과 얼마나 닮았나. R3D-18이라는 영상 AI가 측정.
- **Action 성분 (40%, 최대 가중치)** — 영상 속 팔 움직임이 명령을 얼마나 잘 따랐나. 채점용 고정 IDM(아래)이 영상에서 행동을 되짚어 정답과 비교.
- **MAE (평균절대오차)** — 예측과 정답이 평균 얼마나 어긋났나. 낮을수록 정확. Action 채점에 씀.
- **코사인 거리 / 코사인 유사도** — 두 숫자 묶음이 가리키는 "방향"이 얼마나 다른지(거리) 또는 닮았는지(유사도) 재는 값. 밝기·크기는 무시하고 방향만 본다. DINO·Video 채점에 씀.
- **IDM (역동역학 모델) / extractor (추출기) / 킷 채점기** — 영상만 보고 "무슨 행동을 했길래 이렇게 움직였나"를 거꾸로 알아내는 모델. Action 점수를 매기는 자(고정됨, 우리가 못 바꿈).
- **surrogate IDM (대리 추출기)** — 킷 채점기를 흉내 낸 우리 자체 복제본(학습 보조용).
- **eval / eval 216** — 실제 채점에 쓰는 평가용 216문제. 주최가 정답을 숨긴 채 직접 새로 촬영한 미공개 장면.
- **train (학습 데이터)** — 정답이 딸린 연습 데이터. 공개된 로봇 데이터 128묶음, 사진 약 102만 장.
- **홀드아웃 (holdout)** — 학습에 안 쓰고 따로 빼둔, 우리끼리 채점해보는 "모의고사". **홀드아웃 v2**는 실제 시험과 더 닮게 고친 2차 개정판.
- **GT (Ground Truth, 정답) / GT floor (정답 하한선)** — 진짜 정답 데이터 / 진짜 정답 영상을 그대로 넣어도 도구가 내는 최소 오차(도구 자체 한계).
- **Public / Private 리더보드** — 대회 중 보이는 순위(일부 데이터, 노이즈 많음) / 최종 순위용 숨은 순위(나머지 데이터, 진짜 점수). 최종은 Private 기준.
- **sample_submission** — 주최가 준 제출 예시 파일. 기준값 참고용.
- **셋업 A / 셋업 B** — eval 216문제를 찍은 두 촬영 환경. A는 위에서 내려다본 검은 매트형(154개, 71%), B는 옆에서 올려다본 나무 책상형(62개, 29%).
- **정적 예측 / 정적 영상 (static)** — 시작 사진을 16장 그대로 복사해 "안 움직인다"고 답하는 단순 전략. 현재 우리 팀 최고점.
- **정적 정체선 (≈0.303)** — 정적 영상만으로 받을 수 있는 점수 한계선. 한때 리더보드 상위가 다 여기 몰려서 붙은 이름.
- **과적합 (overfitting)** — 연습·공개 문제에만 맞춰 외워서 진짜 시험(숨은 데이터)에선 오히려 못하는 상태.
- **앵커 (anchor) / 캘리브레이션 (calibration)** — 이미 점수를 아는 제출물을 기준점(앵커)으로 삼아, 로컬 점수만 보고 서버 점수를 예측하게 맞추는 것(캘리브레이션).

### 2.2 모델·생성 기술
- **베이스라인 (baseline)** — 주최가 준 기본 출발 모델. 이걸 이겨야 의미가 있다. 여기선 1,100만(11M) 파라미터의 작은 모델(DynamiCrafter 기반).
- **파라미터** — AI가 학습으로 조정하는 내부 숫자. 많을수록 대체로 똑똑함.
- **latent (잠재 표현) / VAE** — 영상을 작게 압축한 숫자 덩어리(latent)와, 압축·복원을 담당하는 부품(VAE). VAE가 나쁘면 디테일이 뭉개진다.
- **디퓨전 (diffusion)** — 잡음에서 시작해 조금씩 걷어내며 영상을 만드는 생성 방식.
- **UNet** — 디퓨전에서 잡음을 걷어내는 핵심 신경망 뼈대.
- **ddim_steps (스텝 수)** — 잡음을 걷어내는 반복 횟수. 많으면 품질↑·시간↑.
- **eta (η)** — 생성의 무작위성 크기. η=0이면 매번 똑같음(결정론), η=1이면 매번 조금씩 흔들림(확률적).
- **결정론 / 확률적** — 같은 입력이면 항상 같은 결과(결정론) / 매번 조금 다름(확률적).
- **seed (시드, 난수 씨앗)** — 무작위 동작의 출발 숫자. 같으면 같은 결과, 이것만 바꾸면 다른 결과.
- **CFG (Classifier-Free Guidance)** — 조건(행동)을 얼마나 세게 따를지 조절하는 손잡이. 이 대회 베이스라인에선 1.0으로 "봉인"(사실상 끔).
- **action-CFG / action_dropout_prob / null_action_emb / uncond** — 행동에 CFG를 걸기 위한 장치. "행동 없음" 상태(null)를 학습시키려면 학습 중 일부러 행동을 가끔 빼야(dropout ≈0.1) 한다. 베이스라인은 이 값이 0이라 CFG를 바로 못 쓴다.
- **guidance_rescale** — CFG를 켰을 때 세기를 재조정하는 보조 손잡이. CFG가 봉인된 상태에선 무효(no-op).
- **no-op (no operation)** — 켜도 결과에 아무 효과가 없는 설정.
- **best-of-N** — 같은 문제를 seed만 바꿔 N번 만들고, 그중 제일 좋은 하나를 고르는 전략. N배 시간이 든다.
- **오라클 (oracle)** — 정답을 다 아는 이상적 선택. 실전에서 낼 수 있는 최선의 상한선.
- **뭉개짐** — 생성 영상에서 팔이 흐릿한 얼룩으로 녹아버리는 실패 현상.
- **라플라시안 분산 (선명도)** — 이미지가 얼마나 또렷한지 숫자로 잰 값.
- **파인튜닝 (fine-tuning)** — 이미 학습된 큰 모델을 우리 데이터로 조금 더 가르쳐 맞춤화하는 것.
- **LoRA** — 큰 모델 전체를 다시 학습하지 않고 작은 부품만 얹어 값싸게 적응시키는 기법.
- **adaLN (frame-level) / zero-init** — 각 프레임에 행동 정보를 주입하는 모듈. 처음엔 0에서 시작(zero-init)해 안정적으로 학습.
- **REPA / VideoREPA** — 생성 모델 내부 표현을 채점용 DINO 특징에 맞춰 정렬해 학습을 돕는 기법.
- **DRaFT / AlignProp (직접 역전파)** — 점수를 직접 낮추도록 모델을 되짚어 고치는 학습법(주력 후보).
- **cycle consistency (순환 일관성) / cycle loss** — "행동→영상→다시 행동"으로 돌렸을 때 원래 행동과 맞아떨어지는 성질(학습 손실로 사용).
- **RL (강화학습) / GRPO / KL 정규화 / reward hacking** — 보상을 키우는 방향으로 학습(RL·GRPO). KL 정규화는 원본에서 너무 벗어나지 않게 잡아주는 안전장치. reward hacking은 보상 허점만 파고드는 편법.
- **IRASim / Wan2.2-TI2V-5B / DynamiCrafter / CogVideoX·LTX·SVD·Cosmos** — 영상 생성 모델들. IRASim(주력 후보, 파인튜닝 대상), Wan2.2(대안 후보, 50억 파라미터, 라이선스 Apache-2.0), DynamiCrafter(베이스라인 기반), 나머지는 추가 대안.
- **DINOv2 / R3D-18 / CLIP / Conv3D / Bi-GRU** — 특징을 뽑는 기성 AI 부품들(각각 이미지 특징, 영상 특징, 이미지 뜻 요약, 시간 흐름 읽기).
- **OOD (분포 밖, 처음 보는 유형)** — 학습 때 본 적 없는 낯선 입력이라 결과가 못 미더운 상태.
- **flicker (깜빡임)** — 프레임마다 따로 만들어 생기는 어른거림·튐. 시간 흐름을 함께 보는 구조로 줄인다.

### 2.3 로봇·데이터
- **so100 / SO-100 / LeRobot** — 이 대회가 다루는 로봇 팔 종류(so100)와 그 데이터 형식(LeRobot).
- **관절 6축 (액션 6차원)** — 팔의 여섯 움직임: **shoulder_pan**(어깨 좌우), **shoulder_lift**(어깨 상하), **elbow_flex**(팔꿈치), **wrist_flex**(손목 굽힘), **wrist_roll**(손목 회전), **gripper**(집게).
- **리더암 / 팔로워암** — 사람이 조종하는 팔(리더, 그 목표각이 action) / 그대로 따라 하는 팔(팔로워, 그 실제각이 state).
- **observation.state / observation.images** — 팔로워암의 실제 관절각(state) / 카메라 영상(images).
- **에피소드 (episode)** — 로봇이 한 작업을 처음부터 끝까지 한 번 수행한 기록 1건. 총 11,132건.
- **parquet / chunk / info.json** — 데이터를 담은 표 파일 형식(parquet), 묶음 단위(chunk), 각 데이터셋 설명 파일(info.json).
- **SmolVLA** — 로봇 행동 예측용 공개 사전학습 모델(사용된 데이터셋 상당수가 이 대회 train과 겹침).
- **코덱 / av1 / h264** — 영상 압축 방식. av1은 압축률 좋지만 푸는 속도 느림, h264는 흔한 방식.
- **CRF** — 영상 압축 품질 조절값. 낮을수록 고품질·큰 파일.
- **yuv420p / yuv444p** — 색 저장 방식. 420p는 색 정보를 절반으로 줄여 저장(용량↓, 손실 있음), 444p는 그대로(화질 유지).
- **레터박스 (letterbox) / squish / pad** — 규격 크기(320×512)에 맞추는 방법. 레터박스·pad는 비율 유지하고 여백 채우기, squish는 비율 무시하고 늘리기.
- **해상도 / 종횡비 / 어안 렌즈** — 화면 픽셀 수(640×480 등) / 가로세로 비율(4:3·16:9) / 시야 넓지만 둥글게 휘는 렌즈(체스 데이터에 있음).
- **top-down / 측면 상향 뷰** — 위에서 내려다본 시점 / 옆 아래에서 올려다본 시점.
- **사촌 데이터셋 (cousin)** — eval과 똑같진 않아도 겉모습이 닮은 공개 학습 데이터.
- **큐레이션 (curation)** — 학습에 쓸 데이터를 골라내는 일.
- **정규화 (normalization) / z-정규화 (z-score)** — 숫자들의 크기·기준을 맞추는 처리. z-정규화는 평균 0·표준편차 1로 맞추는 것.

### 2.4 통계·수치 기호
- **σ (시그마) / std (표준편차)** — 값이 평균에서 흩어진 폭. "+1.5σ"는 그 폭의 1.5배만큼 밀려남. σ가 크면 같은 오차도 z-정규화에서 "싸게" 매겨진다.
- **median (중앙값) / mean (평균)** — 줄 세웠을 때 한가운데 값 / 산술 평균.
- **corr (상관) / 순위상관** — 두 값(또는 두 순위)이 같이 움직이는 정도. 0이면 무관, 1이면 완전 일치.
- **p95 (95번째 백분위수)** — 값을 줄 세웠을 때 상위 5% 지점(최댓값보다 이상치에 덜 흔들림).
- **편향(bias) vs 산포(variance)** — 일관된 치우침(후처리로 빼기 쉬움) vs 들쭉날쭉함(학습으로만 줄어듦).
- **NaN (결측)** — 값이 비어 있는 자리.

### 2.5 실험·운영·도구
- **E0~E8 / E-final** — 실험 단계 사다리. E0(첫 세션·베이스라인 재현), E1(밤샘 스텝 실측), E2(학습전략), E3(본학습), E4(모델 확정 이후), E8(추론 최적화), E-final(최종 재학습).
- **exp-01·exp-02… / S001·S003…** — 개별 실험 결과 행 번호(exp) / 제출 번호(S). 원장에 기록.
- **원장 (ledger, local_lb.csv)** — 팀의 모든 실험 결과를 한 줄씩 쌓는 공용 장부. 여기 없으면 실험으로 안 침.
- **BOARD.md / LOG.md / 룰북 §N** — 할 일·완료 게시판 / 날짜별 작업 일지 / 팀 규칙 문서의 몇 번째 조항.
- **append-only (추가 전용)** — 남의 기록은 고치지 말고 새 줄만 덧붙이는 규칙.
- **T / Y (역할 코드)** — T는 팀원 쪽(학습 코드·Kaggle·주력 모델 담당), Y는 우리 쪽(서버·분석·문서·자율 실험).
- **trunk-based / main 단일 / PR** — 가지치기 없이 main 한 줄기에서 협업하는 Git 방식(trunk-based). PR은 합치기 전 검토 요청.
- **실효값 ≠ 설정값** — 설정 파일에 적은 값이 코드에서 그대로 쓰인다는 보장이 없다는 교훈(η 사건에서 배움).
- **GPU 종류: T4 / P100 / V100 / A100 / A40 / A6000 / RTX PRO 6000 / 4090 / 5090·Blackwell** — 그래픽 연산 카드들. 대회 채점 기준은 RTX PRO 6000(96GB) 1대. V100은 우리 인하 서버, T4는 Kaggle 무료 카드.
- **VRAM** — GPU 안의 메모리 용량.
- **fp16 / bf16 / fp32 (혼합정밀도)** — 컴퓨터가 소수를 저장하는 정밀도 형식. V100에선 bf16이 흉내만 내 8배 느려 fp16이 정답.
- **Kaggle / RunPod / vast / CDN** — GPU를 빌려 쓰는 클라우드들(Kaggle T4 무료) / 데이터를 빠르게 내려받게 하는 배포 서버.
- **쿼터 (quota) / egress** — 무료 사용 시간 한도(쿼터) / 서버가 바깥 인터넷으로 나가는 통신(egress). egress가 막히면 데이터를 못 받는다.
- **uv / uv.lock / venv / pyproject** — 파이썬 실행 환경·패키지 버전을 고정하는 도구·파일.
- **ckpt (체크포인트)** — 학습된 모델 상태를 저장한 큰 파일.
- **HF (Hugging Face) / PAT / deploy key** — AI 모델·데이터 공유 사이트(HF)와 비공개 저장소 접근용 인증 열쇠(PAT·deploy key).
- **sha256** — 파일이 온전한지 확인하는 지문값.
- **wandb / nbconvert** — 학습 곡선 모니터링 도구(보조) / 주피터 노트북을 스크립트로 바꾸는 도구.
- **벽시계 시간 (wall-clock)** — 로드 포함 실제로 흐른 총 시간.

## 3. 문서별 쉬운 정리

### 01 — 대회 개요
과제는 "로봇 미래 행동 영상 만들기"다. 로봇의 현재 사진 1장(640×480)과 앞으로 할 행동 명령표(16스텝×6관절, 단위는 도)를 받아, 그 로봇이 어떻게 움직일지 16프레임 영상(6fps, mp4)을 만든다. 맨 첫 장은 받은 사진 그대로이므로 실제로 지어내는 미래는 15장이다(시작 상태를 고정해 공정 비교). 채점은 `0.3×DINO + 0.3×Video + 0.4×Action`이고 셋 다 정답과의 거리라 **낮을수록 좋다**. Action이 40%로 가장 크다. 순위는 Public(30%)·Private(70%)이고 최종은 Private. 평가 문제 216개. 규칙: 하루 3회 제출, 외부 데이터 금지, 공개·허용 라이선스 가중치만, API 모델 금지, 파이썬만, 채점 GPU는 RTX PRO 6000(96GB) 1대에서 학습 4일·추론 1시간 이내. 상금 900만 원.

### 02 — 평가 산식 분석
채점 세 항목의 수학적 성질을 파고들어 점수 낮추는 법을 정리했다. DINO·Video는 코사인 거리(방향만 비교, 밝기·코덱 변화에 관대), Action은 MAE로 잰다. 왜 이렇게 나눴나: 사진의 "의미"는 방향에 담겨 코사인이 맞고, 행동은 "크기"가 본질(2배 빠르면 다른 행동)이라 MAE가 맞다. **핵심 결론: 다양성보다 정답에 가까운 결정론적(회귀적) 예측이 유리하다**(코사인 손실 최소해는 여러 정답의 평균 방향이고, 세 항목 모두 정답을 완벽 재현하면 동시에 0이라 서로 안 싸운다). 함정도 짚는다 — 정지 영상은 DINO는 좋아도 Action에서 폭탄, 행동을 너무 세게 밀면(높은 CFG) DINO·Video가 나빠진다. 결론 4가지: ① Action 최우선, ② 하루 3회뿐이라 로컬 채점 파이프라인이 모든 튜닝의 전제, ③ 다양성 억제·고충실 재현, ④ 최종 제출 1개는 Public 과적합 조심해 수동 선택.

### 03 — 데이터 분석
학습·평가 데이터의 실체를 뜯어봤다. train은 100% 공개 로봇 데이터(허깅페이스 SO-100 커뮤니티 128묶음을 6fps로 줄인 것), 총 11,132 에피소드·약 102만 프레임. 원본(30fps·멀티뷰) 추가 반입은 금지. **가장 중요한 발견: 행동(action) ≈ 다음 순간의 실제 팔 자세(state[t+1])**(평균 오차 1.65°, 상관 0.99+). 즉 팔 포즈는 명령이 거의 결정하므로, 모델의 실질 과제는 "명령을 픽셀로 그려내고 + 물체 반응까지 표현"하는 것이다. 채점 실체: DINO(프레임별 특징 16×384), Video(클립 특징 512), Action(고정 추출기가 되짚은 행동을 정답과 MAE). 영상 무리의 사실감이 아니라 **각 문제 정답과 1:1 매칭**이라 다양성은 리스크. 관절끼리 커플링(어깨상하↔팔꿈치 +0.89), 차원별 스케일 격차(std 14~62)가 커서 정규화 필수. (한계: 상관 분석은 128 중 30 표본, 서버 코사인 집계 방식은 미공개.)

### 05 — EDA 검증
위 03의 주장이 실제 데이터(open.zip 8.6GB)와 맞는지 코드로 직접 검증했다. **결론: 노션 리포트 주장은 전부 실측과 일치**, 새로 4가지 발견. ① 베이스라인은 **action_dropout=0.0** — 행동 뺀 경로를 학습한 적 없어 행동 기반 CFG를 바로 못 쓴다. ② **16프레임 미만 에피소드 34개(0.31%)** — 데이터 로더에서 걸러야 함(크래시 방지). ③ **eval 행동 분포가 train과 어긋남**(wrist_roll이 eval +64.4° vs train −29.4°, 약 +1.5σ). ④ 카메라 키가 1개 데이터셋만 예외. 다음 단계로 베이스라인 재현 환경·로컬 리더보드 구축, 미확정 2건은 실제 제출 1회로 캘리브레이션 제안.

### 04 — 파이프라인 (전체 작전 지도)
대회 전 과정의 큰 그림. 목표는 총점 최소화인데 Action이 가중치도 크고 값 범위(0.088~1.148)도 넓어 총점을 지배할 가능성이 높다. 그래서 "팔이 정답대로 움직이게 그리기"가 핵심 과제. Action은 킷이 로컬에서 정확히 계산해줘 제출 전 실측 가능하지만, DINO/Video는 정답이 서버에만 있어 홀드아웃으로 근사한다. 작전은 8단계(S0~S7)와 실험 사다리 E0~E8. 주력은 **Wan2.2(오픈소스 50억 영상 생성기)에 LoRA + 행동 주입(adaLN)을 얹는 파인튜닝**(스크래치 학습은 4일 제약상 무리). 출력 첫 프레임은 시작 사진 그대로 넣어야 정답과 정렬("공짜 정답"). E4(행동 주입)에서 Action이 크게 떨어질 것으로 기대.

### 06 — 조사: 행동 강조 손잡이(CFG)를 지금 쓸 수 있나
**결론: 베이스라인에선 못 쓴다.** CFG는 "조건 있는 예측"과 "조건 없는 예측"을 대비시켜 작동하는데, 베이스라인은 "행동 없음" 상태(null_action_emb)를 학습한 적이 없다(학습 중 행동 빼는 비율이 0이라 그 슬롯이 0인 채 방치). 그래서 조건 없는 예측이 낯선(OOD) 결과다. 다만 구조는 준비돼 있어, 설정 한 줄(dropout≈0.1)만 켜서 이어 학습하면 CFG가 열린다. E1에선 CFG를 봉인하고, 주력 Wan2.2 트랙에선 처음부터 행동 dropout을 넣어 추가 비용 없이 옵션을 확보.

### 07 — 운영 전략 (환경·Git·협업·기록)
**2대 체제**: 로컬 Mac은 코드·문서, GPU 서버는 학습·추론·채점(버전은 킷에 맞춰 고정). 최우선 미결정은 GPU 조달(96GB급). 여러 서버는 분산 학습 대신 실험 병렬로 나눈다 — 긴 학습은 주력 서버, 짧은 실험은 소멸 위험 임대 서버. 최종 제출 영상은 반드시 같은 서버에서 생성(GPU 다르면 결과 미세 차이). **기록 원칙**: 정본은 repo 안 CSV, wandb는 유실돼도 되는 보조. 하루 3회 제출을 CSV로 예산 관리. 주의: 최신 Blackwell 카드는 torch 기본 빌드 미지원이라 cu128 조정 필요.

### 08 — 로컬 리더보드 구축 + GT 자기시험 (중대한 발견)
킷을 그대로 불러와 로컬에서 채점하는 도구를 만들고 정답 영상으로 시험했더니 **충격 발견**: 완벽한 정답 영상인데도 Action 오차가 평균 1.49로 베이스라인 0.579보다 오히려 나빴다. 원인은 정렬·정규화가 아니라 **킷의 행동 추출기가 카메라 뷰(데이터셋)에 따라 성능이 극단적으로 다르다**는 것. 추출기는 평가용 장면엔 맞지만 학습 데이터의 여러 뷰엔 안 맞는다. **그래서: 학습 홀드아웃의 Action 절댓값은 평가치로 못 쓰고, Action은 eval 실측을 정본으로 삼는다.** 또 정지 영상만으로 DINO 0.033·Video 0.039로 낮아, 첫 프레임만 잘 보존하면 이 둘은 감점이 적고 Action이 총점을 지배함이 재확인됐다.

### 10 — 조사: 평가용 216장면의 정체
킷 추출기로 eval 216개를 학습 데이터와 전수 대조. **결론 3가지**: ① eval은 학습 데이터와 겹치는 게 하나도 없다(최대 유사도 0.772 < 판정선 0.85) → 장면 암기는 무효, 일반화가 정답. ② eval은 촬영 세트 2곳(검은 매트 top-down 114 + 나무 책상 측면 58). ③ 손목 각도(wrist_roll)가 전 샘플 체계적으로 +1.5σ 치우침 → eval 하드웨어의 손목 마운트 각도가 학습과 다름. 움직임 있는 구간만 담아 정지 영상 꼼수는 Action에서 벌점. 제안: 홀드아웃·큐레이션을 eval과 닮은 "사촌" 위주로 재편.

### 11 — E0·E1 검증 가설
첫 GPU 작업의 목적은 점수가 아니라 **"이후 실험을 믿을 수 있게 만드는 것"**(가설 H1~H5). H1: 베이스라인 무수정 제출이 Public 0.517일 것(맞으면 로컬-서버 정렬 확인). H2: 우리 제출 CSV의 Action이 0.579 근처(프레임 정렬 확인). H3: 학습 없이 추론 손잡이만 조정해 0.517 깨기 — **단 "베이스라인은 이미 결정론이라 H3 전제 붕괴"라는 후속 판정이 상단에 달림**(12번 참조). H4: 추론 1시간 안에 여러 번 생성(best-of-N) 여유 실측. H5: 정지 영상 앵커가 생각보다 강한지 1회 제출로 확인.

### 12 — 팀원 리포트 반영 (교차검증)
팀원(다른 Claude 세션) 문서 3종을 우리 기록과 대조했다. **새로 안 것**: 팀원이 이미 정적영상으로 Public 2위(0.302949)를 찍었고 1~7위가 다 0.303 언저리("정적 정체선")라, E4 성공 기준을 "로컬·서버 둘 다 0.303 미만"으로 올렸다. 베이스라인 재현 제출로 서버 0.5167을 받아, 두 점수를 앵커로 제출 전 서버 점수를 어림하게 됐다. T4 영상과 주최 영상 점수 차가 0.0003뿐이라 재현 실험에서 GPU 기종은 무관. 프레임별 오차가 첫 컷 0.002 → 16번째 0.201로 90배 커져 후반 컷 가중 근거. **바로잡은 오해**: "베이스라인이 확률적이라 결정론화가 공짜 이득"이라 믿었지만, 코드를 따라가니 설정에 `ddim_eta=1.0`이라 적혀도 실제론 조용히 0.0(결정론)이 쓰이고 있었다. 교훈: **설정값 ≠ 실효값, 코드 경로까지 봐야 한다.** H1·H2·H5 확정, H3 폐기.

### 13 — 팀 룰북 (협업 규칙)
T와 Y가 각자 Claude 세션을 돌리다 겹치거나 기록이 어긋날 위험을 막는 규칙집. 핵심: ① 실험은 exp-01부터 공용 장부에 통합, 제출은 S003부터. 장부에 없으면 실험 아님. ② 로컬 채점 정본은 eval 216 킷 실측(홀드아웃 동작 점수는 참고용). Public은 노이즈라 최종 선택은 로컬 unseen 최고점으로. ③ 시간 기준은 RTX PRO 6000 1대, 추론 16.7초/샘플, 최종 레시피 4일 내 재현. ④ 코드는 GitHub main 한 줄기(scp 금지), 큰 파일은 HF 비공개 경유, **산출물은 세션 끝나기 전 회수 최우선**. ⑤ 인프라: Kaggle T4(짧은 검증)·학교 A100(학습 주력)·임대(보조). ⑥ 정본은 repo docs/, 노션과 어긋나면 repo 우선. ⑦ 슬랙으로 소통하되 **작업 전 착수 선언**, 남의 영역은 BOARD에 이슈로. 룰북 개정만 상호 승인. 마감: 8/20 최종 제출, 8/21 코드, 9/3 발표.

### 14 — 홀드아웃 v2 절차 (모의고사 개편)
실제 평가는 100% 처음 보는 장면인데 기존 모의고사 488개의 unseen 부분이 그 성격을 못 살려, unseen만 갈아끼웠다. 실제 구성이 익숙한 장면 328 + 처음 보는 160임을 확인(앞선 "400+88"은 오류). 앵커가 익숙한 328 위에 서 있어 이 328은 보존하고 unseen만 "닮은 사촌 데이터셋 통째"로 교체. **핵심 긴장**: 사촌은 최고의 연습 문제이자 최고의 학습 재료라 빼면 학습 손실. 그래서 학습 가치 큰 `so100_duck`은 학습에 남기고 다른 사촌 둘로 대표. 최종 **v2 = 익숙한 326 + 사촌 80 + 일반 82 = 488**(seed 0, 재현 검증). 규칙: v2 unseen 4종은 모든 실험 학습에서 제외하고 최종 재학습에서만 복귀, 장부 홀드아웃 수치는 v2만 사용(옛 수치와 안 섞음).

### 15 — E1 분담 제안
E1(추론 스텝 튜닝)이 T 로드맵과 겹칠 위험이 있어 **E1은 Y가 맡고 제출 안 함**, T는 핵심(A100 확보 + Wan2.2 구현)에 집중(T 승인 합의). η 발견 이후 E1에서 만질 손잡이는 스텝 수·guidance_rescale·배치뿐. **E1의 목적은 점수가 아니다** — 베이스라인은 튜닝해도 정적(0.3028)을 못 이긴다. 대신 ① 나중 추론 최적화(E8)의 예행연습이 될 스텝-품질-시간 곡선 방법론, ② 16.7초 한도 대비 실측, ③ 홀드아웃 v2 채점 루프 첫 가동이 목적. 비용 config당 T4 ~70분, 4개 ~5시간.

### 09 — E0 런북 (첫 GPU 세션)
E0의 목적은 새 아이디어 없이 주최 베이스라인을 **있는 그대로 재현**하는 것. 왜: (1) 환경 검증, (2) 이후 모든 실험의 기준 점수 확보, (3) 8/17 제출 1회 요건 겸함. E0는 학습이 아니라 **추론만** 하므로 비싼 카드 불필요(4090으로 E0~E1). 절차: `setup_server.sh`로 데이터 자동 다운·검증·압축해제(데이콘 CDN 무인증 개방 확인) → 베이스라인 노트북을 스크립트로 실행 → mp4 216개 생성 → 킷이 특징 CSV 추출. **추론 시간 꼭 기록**(1시간 제한 대비). Action 평균을 0.579와 비교, 크게 다르면 원인 규명. 예상 Public ≈ 0.517. 주의: 베이스라인은 eta=1.0이라 매번 조금 다름, E0는 그대로 재현만(튜닝은 E1). 킷 requirements 따로 설치 금지(누락 버그가 이미 uv 환경에 반영됨).

### 16 — E1 밤샘 실행 계획 (스텝 감축 실측)
사용자가 자는 동안 자율 에이전트가 돌린 실험. 목표: ① 스텝 수(50/30/20/12)별 속도-품질 곡선 실측, ② 홀드아웃 v2에서 정적·베이스라인 기준행 재측정("재앵커"). **발견 1 — 스텝 줄여도 별로 안 빨라짐**: 50→12로 76% 줄였는데 시간은 21%만 감소(고정 오버헤드가 지배: 모델 로드·인코딩·디코딩·저장). 그래서 추론 최적화의 진짜 레버는 스텝 감축이 아니라 **배치 병렬·전처리**. **발견 2**: step 50 재현 MAE 0.5801(T 실측 0.579와 일치), guidance_rescale은 CFG 봉인 상태에서 무효(영상 바이트까지 동일), 파이프라인 완전 결정론 재확인. **발견 3**: 정적이 베이스라인을 압도(DINO+Video 0.234 vs 0.773). **운영 교훈**: 4차 시도 만에 완주(3차까지 egress 차단으로 중단, 우회 금지 준수). Kaggle GPU 7.2h 사용.

### 17 — E2 학습 전략 초안 (핵심 문서, T 승인 대기)
48시간 EDA 실측 근거의 제안서. 실측과 추정을 명확히 구분한다.
- **§0 요약**: 가장 큰 레버는 best-of-N(N=3에서 −0.023). 단 모델이 정적을 넘어선 뒤에야 의미. 직관 반대 발견 둘 — ① 데이터를 "eval 닮은 순"으로 고르려면 겉모습과 동작을 따로 봐야 함(순위상관 +0.04). ② 최대 실점 축은 wrist_roll이 아니라 shoulder_pan(채점 z-정규화가 wrist_roll 오차를 싸게 매김).
- **§1 큐레이션**: 확정 제외 = 16프레임 미만 34개 + 유일한 10fps `dragon-95/so100_sorting` + 홀드아웃 v2 unseen 4종. `Chojins` 체스 4개는 겉모습 최하위지만 프레임 12.7%라 완전 제외 대신 가중치 축소(1/3) A/B 후 결정. **§1.3 핵심 원칙 — 전역 랭킹으로 자르지 마라**: 겉모습 유사도는 모델이 어디서 실패할지 못 맞혔다. 사촌 많은 셋업 B에서 오히려 모델이 훨씬 못하고(MAE 0.7868 vs A 0.5075), 실패 형태는 "틀린 동작"이 아니라 **뭉개짐**(B가 1.6배 심함, 선명도 유지율 A 66.6% vs B 40.5%). → 겉모습 랭킹은 보조로만, 세그먼트별 실측 오차를 우선순위로. [주: 이 §1.3에 붙어 있던 "셋업 B의 낯선 시점 탓" **추정은 이후 서버 분석에서 기각됨** — 실측(뭉개짐·선명도)은 유효하나 원인은 다시 미해결. docs/21 정정 제안 참조.]
- **§2 정규화**: wrist_roll은 원점만 밀린 문제지만 z-정규화에서 표준편차가 커 실점 비중 6.8%로 꼴찌 → "옳지만 값싼" 개선, 학습 안정성 목적만. 필수: 어떤 변환이든 킷 채점기 코드 경로까지 정합 확인(η 사건 재발 방지).
- **§3 예산 배분**: 실점이 shoulder_pan·lift·elbow(합 62.8%, 큰 관절)에 몰림 → 여기 집중. 오차 대부분이 산포라 후처리 아닌 **학습으로만** 준다.
- **§4 학습 예산**: 최종 레시피는 96GB 1대 4일 내 재현. 추론 step 50이 10.43초/샘플(한도 16.7초 내), 216개 50.5분(한도 1시간, 여유 ~9.5분). 여유가 커지 않아 이 예산 안에선 best-of-N이 N=1 외 불가. V100은 fp16이 정답.
- **§5 재현성 주의**: 생성 코드가 seed를 루프 전 1회만 부르고 난수를 순차 소비 → **배치 크기 바꾸면 결과 영상이 달라짐**. 최종 제출은 배치·seed·순서 고정하고 중단 없이 한 번에.
- **§6 공짜 개선**: yuv420p는 CRF 0에도 +0.002 손실이 남지만 yuv444p는 손실 ≈0(색 절반 축소가 원인). 총점 기여 ≈ +0.0008, 비용은 파일 8%. 코드 한 줄이지만 킷 계열이라 T 판단 요청.
- **§6.5 best-of-N**: N=3에서 −0.023. 관문이던 "제출 전 최선 고르기"는 Action(40%, 로컬 계산 가능) 기준 선택으로 오라클의 91% 회수, 화질 손실 없음. 배치 2 + best-of-3 권장(14.1초/샘플). **적용 시점은 E4 이후**(모델이 정적 넘어선 뒤), 이득은 모델 seed 분산에 의존해 재측정 필요.
- **§6.6**: 이종(정적↔베이스라인) best-of-2는 무익(216 중 이득 나는 샘플 2개). best-of-N은 같은 모델 변형끼리만.
- **§7 T 승인 필요**: best-of-N 채택·설정, 제외 목록, Chojins 가중치, 셋별 쿼터, wrist_roll 정렬, 최종 제출 고정.

### 18 — train 전수 카탈로그 (48h Phase 1)
학습용 128묶음을 하나도 빠짐없이 조사해 표로 정리(V100 40코어 병렬, 60초). 규모 수치(11,132 에피소드·102만 프레임) 실측 100% 일치, 액션 6차원 결측 0. **데이터가 균질하지 않음** — 흡수해야 할 이질성 4종: 해상도 3종(4:3·16:9 섞임 → 규격 맞출 때 여백 비율이 학습에 힌트로 샐 수 있음), 코덱 2종(av1 디코딩 느림), fps 예외 1개(10fps라 같은 16장이 담는 시간이 1.6초로 다름), 카메라 키 예외 1개. **최대 발견 — wrist_roll 불안정**: 묶음 간 편차 47.78(2위의 약 2배)로, 이 축 숫자는 "무슨 일을 하나"보다 "누가 어떻게 영점을 맞췄나"를 더 담음. 부수 정정 2건(docs/05가 지목한 예외 데이터셋은 train에 없음; 16프레임 미만 34개 중 27개가 빈 녹화 → "16 미만 제외" 단순 규칙으로 충분, 크래시 방지 목적). 주의: 체스 `Chojins` 4개가 프레임 12.7% → 균등 샘플링 시 학습을 지배하므로 비중 조절 필요.

### 19 — eval 유사도 랭킹 (48h Phase 2)
학습 데이터가 103만 장이라 eval과 닮은 묶음에 힘을 실으려 DINO로 128묶음의 "시험 닮음" 순위를 매김(묶음당 대표 24장, 움직임 담긴 중간 장면). **핵심**: 판정선(0.85) 넘는 묶음 0개(최고 0.8085) → eval 100% 미공개 확인. 체스가 최하위권. eval과 안 닮은 하위 20묶음이 프레임 24.4% → 큐레이션 여지 큼. **중요한 반전 — 이 순위만으로 부족**: 원래 결론은 "사촌 빈약한 셋업 A가 방치될 위험"이었으나 실측은 반대 — 닮은 데이터 많은 **B에서 모델이 훨씬 못함**(MAE 0.7868 vs A 0.5075). DINO 겉모습은 "무엇이 찍혔나"는 봐도 "어느 각도인가"(시점 기하)는 못 봄. → 겉모습 순위는 1차 기준이 아니라 후보 좁히는 보조로. (원 서술은 지우지 않고 정정 블록 추가.)

### 20 — 복귀 보고서 (7/20~7/22 자율 실행)
넘겨받은 계획 전량 완료 + 계획 외 분석 7건. 대회 제출 0건, T 영역 불가침. **발견 요약**: ① **best-of-N** 검증(N=3 −0.023, Action 기준 선택이 오라클 91% 회수) — 단 모델이 정적 넘어선 뒤 얹는 카드. ② **고칠 곳 정정**: 데이터상 최악으로 보인 wrist_roll이 실점 비중은 꼴찌(6.8%), 진짜는 어깨·팔꿈치(62.8%). ③ **데이터 고르는 기준 하나론 부족**: 겉모습·동작 순위 무관(+0.04), 실패 형태는 뭉개짐(B 1.6배). 현 베이스라인(11M) 개선 출발점 부적합 → 모델 교체 뒷받침. ④ **같은 설정도 같은 영상 안 나옴**(평균은 재현, 216 중 141 상이) → 실험 비교는 평균만, 최종은 한 서버 한 번에. 룰북 §6 개정 불필요 확인. ⑤ **V100 서버 합격**: 채점 Kaggle과 16자리 일치·2배 빠름, 생성 10.4초(한도 내), bf16 함정. ⑥ 부품 5개 누락 수복. ⑦ **yuv444p** 공짜 +0.0008(T 판단 요청). ⑧ 문서 오류 2건·재량 판단 기록(사용자 사후 승인 완료). 남은 결정: T 승인 필요 기술 제안 5건(docs/17 §7).
