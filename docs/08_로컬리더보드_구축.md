# 로컬 리더보드 구축 + GT(정답) 자가시험 결과 (2026-07-18)

> **GT self-test(정답 자가시험)** = "진짜 정답 영상을 채점기에 넣으면 몇 점이 나오나"를 재보는 시험. 원래 0점(완벽)에 가까워야 정상인데, 여기서 충격적인 결과가 나왔다.

## 구축물 (local_eval/)
- `kit_bridge.py` — 킷을 손대지 않고 그대로 불러와 추출기 3종·전처리·채점식 재사용. DINO 합치기는 프레임평균/펼치기 두 방식 다 계산
- `make_holdout.py` → `holdout.json` — 2단 분할 확정 (seed 0으로 고정): 익숙한 장면 532 에피소드 + 처음 보는 7개 데이터셋(376 에피소드)
- `score.py` — 생성 영상 폴더 → 대회 채점식으로 점수 매기기 (E0/E1부터 사용)
- `gt_selftest.py`, `debug_action.py` — 점수 바닥(최소 오차) 실측·검증
- 환경: .venv(파이썬 3.11, torch 2.7.1로 킷과 맞춤). **킷 요구사항 버그: omegaconf 패키지 누락**(모델 로드에 필요) — 서버 세팅 시 반드시 설치

## ★ 핵심 발견: 킷의 행동 추출기(IDM)는 train 도메인에서 못 믿는다
정답(GT) 영상(train 홀드아웃 12개, 완벽한 정답)을 채점기에 넣은 결과:

- **Action 바닥값 평균 1.49** (범위 0.54~2.09) — 베이스라인의 eval Action 0.579보다 **오히려 나쁨** (정답인데도!)
- 디버깅으로 배제한 원인 후보: 시점 어긋남(±2칸 밀어봐도 무영향), 자세 예측 방식, 정규화 단위(도(deg)로 하면 오차 70+, z-정규화 공간이 맞다고 확정)
- 확정 해석: 추출기가 **데이터셋(카메라 시점)에 따라 성능이 극단적으로 다름**. 어떤 데이터셋(sihyun77)은 0.54로 준수, 어떤 곳은 어깨좌우/어깨상하/팔꿈치를 표준편차의 2~4배로 틀림. 정지 영상과 정답 영상의 Action이 거의 같다는 점(1.51 vs 1.49)도, 추출기가 그 시점에선 팔의 절대 자세를 못 읽는다는 증거
- 추론: 추출기는 eval 도메인(주최가 직접 촬영, 위에서 내려다본 시점으로 추정)엔 잘 맞고 커뮤니티 train의 여러 시점엔 안 맞음. eval에서 예시 제출의 Action이 0.088까지 내려가는 것과 앞뒤가 맞음

## 전략적 함의 (파이프라인 수정 사항)
1. **train 홀드아웃의 Action 절대값은 eval 점수 예측에 쓸 수 없다.** 로컬 리더보드에서 Action은 **eval 실측**(킷이 정확히 계산, 216샘플 전부)을 정본으로, 홀드아웃 Action은 상대 비교 참고로만.
2. DINO/Video 근사(프록시)는 홀드아웃 유지 (이 항목들은 정답 vs 정답 = 0으로 정상 작동 확인됨).
3. 정지 영상 기준점: DINO 0.033 / Video 0.039로 매우 낮음 — **첫 프레임만 잘 보존해도 DINO/Video는 큰 감점이 없다**는 뜻. 뒤집어 말하면 이 두 항목의 변별력은 생각보다 작고, Action이 총점을 더 지배한다 (베이스라인 역산의 DINO+Video 0.48은 생성 품질이 심하게 나쁘다는 신호).
4. 자체 IDM(surrogate) 학습 시: train 전체가 아니라 **추출기가 잘 작동하는 도메인**(eval 닮은 시점) 위주로 골라 쓰는 것(큐레이션) 고려. eval Action 실측 루프가 최종 심판.
5. 정답 자가시험의 "이론상 최저 총점" 개념은 train 도메인에선 무의미해짐 — eval 도메인의 바닥은 예시 제출 최소값(0.088)이 힌트 (진짜 바닥은 E0 제출로 탐색).
