# 로컬 리더보드 구축 + GT self-test 결과 (2026-07-18)

## 구축물 (local_eval/)
- `kit_bridge.py` — 킷 무수정 import, 추출기 3종·전처리·산식 재사용. DINO 집계는 프레임평균/flatten 병산
- `make_holdout.py` → `holdout.json` — 2단 분할 확정 (seed 0 불변): in-domain 532 에피소드 + unseen 7개 데이터셋(376 에피소드)
- `score.py` — 생성 영상 디렉토리 → 대회 산식 채점 (E0/E1부터 사용)
- `gt_selftest.py`, `debug_action.py` — 점수 바닥 실측·검증
- 환경: .venv(py3.11, torch 2.7.1 킷 정합). **킷 requirements 버그: omegaconf 누락** (ckpt 로드에 필요) — 서버 세팅 시 필수 설치

## ★ 핵심 발견: 킷 action extractor는 train 도메인에서 신뢰 불가
GT 영상(train 홀드아웃 12개, 완벽한 정답)을 채점기에 넣은 결과:

- **Action floor 평균 1.49** (범위 0.54~2.09) — 베이스라인의 eval Action 0.579보다 **나쁨**
- 디버깅으로 배제한 가설: 정렬 시프트(±2 무영향), state 예측(무차이), 정규화 단위(deg면 MAE 70+, z-공간 확정)
- 확정 해석: extractor가 **데이터셋(카메라 뷰)에 따라 극단적으로 다른 성능**을 보임. 어떤 데이터셋(sihyun77)은 0.54로 준수, 어떤 곳은 pan/lift/elbow를 2~4σ 틀림. 정지 영상과 GT 영상의 Action이 거의 같다는 점(1.51 vs 1.49)도 extractor가 해당 뷰에서 절대 포즈를 못 읽는다는 증거
- 추론: extractor는 eval 도메인(주최측 자체 수집, top-view 추정)에 잘 맞고 커뮤니티 train 뷰 다수에는 안 맞음. eval에서 sample_submission Action이 0.088까지 내려가는 것과 정합

## 전략적 함의 (파이프라인 수정 사항)
1. **train 홀드아웃의 Action 절대값은 eval 예측치로 쓸 수 없다.** 로컬 리더보드에서 Action은 **eval 실측**(킷이 정확 계산, 216샘플 전수)을 정본으로, 홀드아웃 Action은 상대 비교 참고로만.
2. DINO/Video 프록시는 홀드아웃 유지 (이 성분들은 GT vs GT = 0으로 정상 동작 확인).
3. 정지 영상 앵커: DINO 0.033 / Video 0.039로 매우 낮음 — **첫 프레임만 잘 보존해도 DINO/Video는 큰 감점이 없다**는 뜻. 반대로 말하면 이 두 성분의 변별력은 생각보다 작고, Action이 총점을 더욱 지배 (베이스라인 역산의 DINO+Video 0.48은 생성 품질이 심하게 나쁘다는 신호).
4. surrogate IDM 학습 시: train 전체가 아니라 **extractor가 잘 작동하는 도메인**(eval 유사 뷰) 위주 큐레이션 고려. eval Action 실측 루프가 최종 심판.
5. GT self-test의 "이론 최저 총점" 개념은 train 도메인에선 무의미해짐 — eval 도메인 바닥은 sample_submission 최소값(0.088)이 힌트 (진짜 바닥은 E0 제출로 탐색).
