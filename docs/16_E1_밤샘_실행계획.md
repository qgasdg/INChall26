# E1 밤샘 실행 계획 (2026-07-19 야간, Y 클로드 자율 실행)

> 착수 선언 완료([슬랙](https://inchall26.slack.com/archives/C0BJ7PWLLN6/p1784393370046249), 7/19). 근거: [15_E1_분담_제안.md](15_E1_분담_제안.md)(T 승인) + [14 §4 재앵커](14_홀드아웃_v2_절차.md). 실행자 = Y측 클로드 백그라운드 에이전트, 사용자 취침 중 자율 진행.

## 목표 (아침까지 산출물)
1. **E1 스텝-품질-시간 곡선**: ddim_steps 50/30/20/12 × eval 216 생성 + 킷 Action MAE + 샘플당 추론 시간 실측 → 16.7s/샘플 예산 대비 감축 곡선.
2. **홀드아웃 v2 재앵커**: v2 unseen 162(사촌 80+일반 82)에서 정적·베이스라인(step 50) D+V 재측정 → 원장 기준행.
3. 원장([local_lb.csv](../results/local_lb.csv)) 행 추가 + LOG + 슬랙 완료 보고.

## 사전 확정 사항 (재조사 불필요)
- 생성 스크립트 = `open/baseline/challenge_kit/scripts/inference/generate_baseline_videos.py`, `--ddim-steps` 오버라이드 지원. eval config의 ddim_kwargs: steps 50, **uncond_scale 1.0(CFG 봉인 상태), guidance_rescale 0.7**, uniform_trailing, eta 1.0.
- **홀드아웃 생성 트릭**: challenge 입력 포맷 = `images/<id>.png`(첫 프레임) + `actions/<id>.npy`(16×6) → v2 unseen 샘플을 이 포맷으로 로컬 변환(episode_io, 윈도우 = start부터 16프레임)하면 생성 스크립트 **무수정 재사용**.
- Kaggle: 계정 qgasdg, `.venv/bin/kaggle`, **push 시 `--accelerator NvidiaTeslaT4` 필수**, 마운트 `/kaggle/input/datasets/qgasdg/<slug>/`, pip 레시피 = 이전 커널(`inchall26-static-csv`) 그대로(numpy<2 최후 강제). 쿼터 잔여 29.88h.
- 기존 dataset `inchall26-static-bundle`(146MB) = submission_kit + data/eval. 신규 업로드 필요분: challenge_kit 코드+ckpt(84MB), action stats json, unseen 4개 데이터셋 원본(~108MB), 변환된 challenge 포맷 입력, local_eval 채점 코드.

## 실행 단계
| 단계 | 내용 | 예상 |
|---|---|---|
| P0 로컬 준비 | v2 unseen 162 → challenge 포맷 변환 · score.py v2 대응(--holdout 인자, start 윈도우, v2 티어명) · `inchall26-e1-bundle` 데이터셋 업로드(~300MB) | ~1h |
| P1 스윕 커널 | 커널 1개에서 4 config 순차: 생성(타이밍 실측) → 킷 추출 → Action MAE vs GT npy. 산출 = 곡선 CSV + 로그 | ~5h (config당 ~75분) |
| P2 재앵커 커널 | v2 unseen 162 베이스라인 생성(step 50) + 정적, D+V 채점(in-kernel) | ~2h |
| P3 정리 | 출력 회수 → local_lb.csv 행 추가(exp-02~) · LOG · 본 문서에 결과 추기 · 슬랙 보고 · 커밋/푸시 | ~30m |

## 판단 규칙 (에이전트 재량 범위)
- P1·P2는 커널 분리(세션 한도 회피). 동시 실행 불가 시 P1 먼저(스윕이 주 목표).
- 채점 모델(DINO 등)이 커널에서 다운로드 필요하면 kernel-metadata `enable_internet: true` 허용. 불가 시 가중치를 번들에 동봉.
- guidance_rescale 스윕은 **시간 남으면**: CFG 1.0이라 no-op 가능성 — step 20에서 rescale 0.0 vs 0.7 한 쌍만 실측해 no-op 여부 판정.
- 실패 시 손절: 같은 원인 3회 실패면 해당 단계 보류하고 결과·원인만 기록 (쿼터 낭비 금지).
- 산출물 회수 최우선(룰북 §5) — 커널 종료 전 output 확인, 영상 원본은 회수 말고 점수·CSV만.

## 제약 (룰북 준수)
- 제출 없음 (E1 정의). `results/` CSV는 append-only. T 영역(Kaggle 노트북 = T 소유는 T의 것만 — 내 커널은 별도 slug) 불가침.
- 작업 중 간간이 슬랙 확인(§8), 완료·중단 시 슬랙 보고.
