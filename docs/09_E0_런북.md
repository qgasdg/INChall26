# E0 런북 — 첫 GPU 세션 (베이스라인 재현 + 제출 1회)

> 목표: 환경 검증 → 베이스라인 재현 → 데이콘 제출 1회(팀 구성 전 요건 겸함, 8/17 한) → 로컬↔서버 캘리브레이션 기준점 확보. **몇 시간 안에 세션 종료**가 목표. 실험 ID = exp04.

## 0. 비용 전략
E0는 **추론만** 하므로 96GB급이 필요 없다. 저렴한 카드(4090 24GB 등)로 E0~E1을 끝내고, 고가 학습 서버(96GB급)는 E3 진입 시점에 별도 결정 — 07 §1.1의 주력/보조 분담과 정합.

## 1. 렌트 전 준비물 (사용자)
- [ ] 대여처 계정 + 결제 수단, SSH 공개키 등록
- [ ] GitHub 접근: private repo라 서버에서 clone하려면 PAT(read-only fine-grained 권장) 또는 deploy key
- [ ] HF 계정 토큰 (베이스라인 backbone 자동 다운로드·추후 Wan2.2용. 공개 모델이라 토큰 없이 될 수도 있으나 rate limit 대비)
- [x] open.zip 반입: **확인 완료(7/18) — 데이콘 CDN(`cfiles.dacon.co.kr/competitions/236736/open.zip`)이 인증 없이 접근 가능** (HEAD 200, 크기 일치). setup_server.sh가 자동 다운로드하므로 반입 작업 불필요. (백업 경로: 집 업링크 35.5Mbps 실측 → scp 시 ~32분)

## 2. 세션 절차
```bash
# (서버) 1. 코드 + 데이터
git clone https://github.com/qgasdg/INChall26.git && cd INChall26
bash scripts/setup_server.sh        # uv sync → open.zip 자동 다운로드 → sha256 대조 → 압축해제 → GPU·킷 검증

# 2. 베이스라인 실행 (노트북 → 스크립트 변환 후 headless 실행)
cd open/baseline
../../.venv/bin/jupyter nbconvert --to script baseline.ipynb   # jupyter 없으면: uvx --from nbconvert jupyter-nbconvert
# 변환된 스크립트 검토 후 실행 (backbone.ckpt 자동 다운로드 포함)
cd ../.. && uv run python open/baseline/baseline.py
```
- 출력: `open/submission_kit/input_videos/*.mp4` 216개 → 킷이 `submission_features.csv` 생성 (노트북 5단계에 포함)
- **추론 벽시계 시간 기록** (1h 제한 대비 기준점)

## 3. 검증 → 제출 → 실측
1. `submission_features.csv`의 Action 실측 확인 — sample_submission 평균 0.579와 대조 (크게 다르면 제출 전 원인 규명)
2. mp4 스펙 확인: 정확히 16프레임, 320×512 또는 640×480
3. CSV를 로컬로 회수 → **데이콘 제출은 브라우저에서** (예상 Public ≈ 0.517, 리더보드 다수 수렴값 — 크게 다르면 캘리브레이션 어긋난 것)
4. 로컬 리더보드 실측: `local_eval/score.py`로 홀드아웃 채점 (구축 상세 docs/08) → 서버 점수와의 관계가 이후 모든 실험의 캘리브레이션 기준
5. 기록: `results/local_lb.csv` + `results/submissions.csv`에 exp04 행 추가, LOG.md 갱신, 커밋·푸시
