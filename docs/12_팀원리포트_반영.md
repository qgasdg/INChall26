## 1. 핵심 새 정보 (우리가 몰랐던 것)

- **팀원이 이미 Public 2위 (0.302949)** — 정적영상(조건 프레임 ×16) 제출 S001. **리더보드 1~7위 전부 ~0.303 = "정적 정체선"**. E4(액션 모듈) 성공 기준 = 로컬·서버 모두 0.303 미만으로 상향됨.
- **베이스라인 재현 제출 완료 (S002 = 0.5167429)** — Kaggle T4×2에서 E0 완주(216/216, 18.87s/샘플). sample_submission과 Δ0.00034 → 0.51708 클러스터 = 베이스라인 무수정 확정.
- **서버 캘리브레이션 앵커 2점 확보**: 정적 D+V 0.4364 / 베이스라인 D+V 0.9502 → 제출 전 서버 점수 근사 예측 체계 성립.
- **하드웨어 불변 실증**: T4 생성물과 주최측 생성물은 픽셀이 달라도(DINO cos 0.82) 점수 차 0.0003 → 재현 실험에서 GPU 기종 걱정 불필요 (07 §1.1의 "같은 카드" 규칙은 미세 비교 실험에만 유지).
- **프레임별 DINO 오차 t=0 0.002 → t=15 0.201 (90배)** → 후반 프레임 가중 손실 근거.
- **시간 예산 정밀화**: 추론 한도 = **16.7s/샘플** (RTX PRO 6000 기준). T4 실측 18.87s → 스텝 감축 필요.
- **W2 결정(팀원측)**: Wan2.2-TI2V-5B 파인튜닝 + **학교 A100** (신청 중) — 우리 04 주력과 동일 방향. DynamiCrafter-FT는 플랜 B.
- SmolVLA 노하우: 동결 백본+소형 전문가 모듈(시간 예산 정합), VLM 재주석·품질 큐레이션, cross-attn+인과 구조 우위, FM>L1 회귀.

## 3. ★불일치 해소 — 베이스라인 η (우리 코드 추적으로 확정)

- 우리 04·LOG·11(H3)의 전제: "베이스라인 η=1.0 확률적 → 결정론화 cheap win" — **폐기**.
- 팀원 F1 정정이 맞음을 코드로 직접 확인: config `ddim_eta: 1.0` → `generate_baseline_videos.py:104-118`에서 `**sample_kwargs`로 전달 → `DDIMSampler.sample()`의 실제 인자는 `eta=0.0`(기본값), `ddim_eta`는 말미 `**kwargs`에 **조용히 삼켜짐** → `make_schedule(ddim_eta=eta)`에 0.0 전달. **베이스라인은 이미 결정론.**
- 교훈(팀원 표현 채택): "설정값 ≠ 실효값 — 코드 경로까지 추적해야 확정".
