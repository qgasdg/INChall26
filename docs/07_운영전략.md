## 1. 환경 전략 — 2-머신 체제

| | 로컬 Mac (현재) | GPU 서버 (조달 필요) |
|---|---|---|
| 역할 | 코드 개발, EDA, 로컬 리더보드 로직 개발, 문서 | 학습·추론·킷 실행·로컬 리더보드 실측 |

| 데이터 | `open/` (원본 open.zip 보존) | 데이콘에서 직접 다운로드 후 sha256 대조 (8.6GB 왕복 업로드 금지) |

- 최종 재현(S7)은 RTX PRO 6000 96GB 1장 기준이므로, 조달 GPU가 달라도(예: A100/H100) **96GB VRAM·4일 벽시계 기준으로 예산 계산**을 맞춘다.
- **GPU 조달 = 최우선 미결정 항목.** 후보: vast.ai / RunPod에서 RTX PRO 6000(또는 동급 96GB). E0(베이스라인 재현+제출)가 이것에 막혀 있음.

### 1.1 멀티 서버 운영 (여러 곳에서 GPU를 빌리는 경우)

전제: 서버 간 분산 학습(DDP)은 **하지 않는다** — 사이트 간 네트워크로는 무의미하고, 최종 재현 기준도 단일 GPU다. 멀티 서버의 가치는 **실험 사다리의 병렬화**다.

- **역할 분담 (서버 = 실험 단위):** 한 실험은 반드시 한 서버에서 끝낸다. 예시 분담 —
  - **주력 서버** (장기 점유 가능한 쪽, 예: 연구센터): 오래 걸리는 학습 = E3 도메인 적응, E4~E6 본 학습. VRAM 큰 쪽이 여기.
  - **보조 서버** (임대 등): 짧은 실험 병렬 = E1 추론 스윕, ablation, 로컬 리더보드 실측, best-of-N 생성. 소멸 리스크 있는 쪽이 여기(짧은 작업만 두면 잃을 게 없음).
- **부트스트랩 스크립트 1개** (`scripts/setup_server.sh`): git clone → uv sync → open.zip 다운로드+sha256 대조 → 킷 설치 검증까지. 어느 서버든 이 스크립트 하나로 동일 상태 — 서버별 수동 셋업 금지. 연구센터 서버는 sudo 불가·공유 자원일 가능성이 높은데 uv는 유저 공간에서 다 되므로 문제없음. (확인 필요: 연구센터 아웃바운드 인터넷 — HF 가중치·데이콘 다운로드 가능 여부. 막혀 있으면 로컬에서 받아 올리는 경로 필요.)
- **서버 프로필 config**: GPU가 다르면 (VRAM·아키텍처) batch size·precision이 달라진다. `configs/server_<이름>.yaml`로 하드웨어 종속 값만 분리, 실험 config는 서버 무관하게 유지. 시간 예산은 **RTX PRO 6000 96GB 기준으로 환산 기록** (최종 4일 제약의 기준 카드).
- **결과 정합성**: `results/local_lb.csv`에 **server 컬럼 추가**. GPU 아키텍처가 다르면 cudnn 커널 차이로 생성 결과가 미세하게 달라질 수 있으므로, **최종 제출물 생성(추론)과 그 직전 비교 실험은 반드시 같은 서버에서** 수행.
- **아티팩트 허브 1곳**: 서버끼리 직접 통신은 기대하지 않는다(연구센터 방화벽·임대 인스턴스 소멸). ckpt·생성물 이동은 중앙 허브 경유 — **HF private repo 권장** (무료·대용량·`hf_hub` CLI로 양방향, 단 private 유지 철저). 코드는 여전히 git으로만.
- **실험 큐 = LOG.md에 서버별 섹션**: "어느 서버에서 뭐가 돌고 있는지"를 LOG에 명시해 중복 실행·유휴 방지. 임대 서버는 큐가 비면 즉시 반납(비용).
- **규정 해석 주의**: 학습 4일 제약은 통상 "최종 선택 모델의 재현" 기준이지 탐색 총량 제한이 아니지만, **최종 레시피(전처리→학습→추론)는 단일 GPU 4일 안에 들어와야 한다**. 병렬은 탐색 가속용이고, 최종 제출 직전에 4일 예산으로 수렴하는지 반드시 계산. 애매하면 데이콘 토크로 주최측에 질의.

## 2. Git / GitHub

- **Private repo** (`gh` 로그인: qgasdg). 코드 유출 방지 + 8/21 코드 제출 시 이력이 재현성 증빙이 됨. 팀원은 collaborator 초대.
- **버전 관리 대상 = 코드·문서·config·결과 CSV만.** 데이터(`open/`, `open.zip`), venv, 가중치, 생성 영상, wandb 로그는 전부 ignore — 원본은 open.zip과 서버 스토리지가 담당.
- **브랜치: trunk-based.** 소규모 단기 대회라 main 직커밋 기본, 구조가 큰 변경(아키텍처 교체 등)만 짧은 브랜치+PR. 리뷰로 속도 죽이지 않는다 — 실험 코드의 정합성은 로컬 리더보드 점수가 검증한다.
- 커밋 메시지: 실험 관련 커밋은 `expNN:` 접두 (예: `exp04: E1 결정론 추론 스윕`). **실험 실행 시점의 커밋 해시를 실험 기록에 남기는 것**이 이 규칙의 목적.
- 서버↔로컬 코드 동기화는 **git으로만** (rsync/scp로 코드 나르기 금지 — "서버에서만 고친 코드" 유실 사고 방지). 서버에서 급히 고친 것도 즉시 커밋·푸시.

### 디렉토리 구조 (목표)
```
INChall26/
  docs/          # 조사·의사결정·LOG (현행 유지)
  scripts/       # 일회성 EDA·유틸
  local_eval/    # 로컬 리더보드 (킷 체인 재현)
  src/           # 학습·추론 코드 (E2+ 진입 시 생성)

```

## 4. 실험(학습) 트래킹

이원 체계: **정본 = repo 내 CSV** (점수·제출), **보조 = wandb** (학습 곡선·GPU 모니터링).

### 실험 단위
- 실험 ID `expNN` — 노션에서 exp03까지 사용됨 → **exp04부터 이어서** 번호 부여. E0~E8 사다리 단계와는 별개 축(한 E단계에 expNN 여러 개).
- 실험 1개 = `configs/expNN_이름.yaml` 1개 + 커밋 해시 1개. 단일 변수 변경 원칙(S6).

### 정본 CSV (repo, 매 실험 후 커밋)
- `results/local_lb.csv`: expNN, 커밋 해시, E단계, 변경점 1줄, **로컬 in-domain 점수 / unseen 홀드아웃 점수 / Action 실측(MAE)**, 추론 소요시간, 날짜. → ckpt 선택·최종 제출 선택의 유일한 근거.
- `results/submissions.csv`: 날짜, expNN, 제출 파일, **Public 점수**, 대응 로컬 점수. → 로컬↔서버 캘리브레이션 추적 + **3회/일 제출 예산 관리** (제출 전 이 파일 확인이 규칙).

### wandb (보조)
- 용도: loss 곡선, 학습 중 검증 지표, GPU 사용률/VRAM — 4일 예산 소진 감시.
- 개인 계정 + 팀원에게 뷰 링크 공유 (무료 팀 플랜 제약 회피). 서버 네트워크 문제 시 `wandb offline` → 나중 sync. run 이름 = expNN.
- wandb는 유실돼도 되는 데이터만 담는다 — 점수·의사결정 근거는 반드시 CSV로.

### 체크포인트 정책
- ckpt는 서버 스토리지에만 (repo 금지). 실험별 `expNN/` 디렉토리, **로컬 리더보드 최고 ckpt만 유지**하고 중간 ckpt는 스토리지 압박 시 삭제.
- 최종 제출 후보 ckpt는 별도 백업(클라우드 스토리지 1곳) — 서버 인스턴스 소멸 대비. 임대 GPU는 언제든 날아갈 수 있다는 전제로 운영.
