## v1.3에서 무엇이 바뀌었나 (뒤집힌 핵심 결정)
1. **주력 모델을 Wan2.2에서 IRASim으로 갈아탔습니다.** IRASim은 (시작 사진 1장 + 행동 15스텝 → 16프레임)을 원래부터 만드는 모델이라 우리 과제와 구조가 딱 맞습니다. 프레임마다 행동을 주입하는 방식(frame-level AdaLN)이 사전학습에 이미 들어 있고, 영상을 압축하는 부품(VAE)이 시간을 뭉개지 않아 6fps 느린 영상에서도 움직임이 번지지 않습니다. 라이선스도 가장 안전한 Apache-2.0이고 48GB GPU로 학습·추론이 됩니다. 반대로 Wan2.2는 시간 압축 탓에 움직임이 번질 위험 + 행동 주입을 따로 이식하는 수술 필요 + A100 GPU 의존이라 **서브(예비)로 내렸습니다** — E2 관문(G5·G6)을 통과할 때만 병행합니다.
2. **"흔들림 없이(결정론) 뽑는 게 최적"이라던 가설이 실측에서 깨졌습니다.** 추론 설정을 14가지로 훑어보니(E1), 매번 조금씩 다르게 뽑는 eta=1.0이 결정론(eta=0)을 완전히 이겼습니다(0.2011 vs 0.2198, 격차가 노이즈의 9배). 이론상으론 "평균 방향"이 유리해 보였지만, 특징을 뽑는 과정이 비선형이라 그 평균에 해당하는 영상을 애초에 만들 수가 없었던 거죠. 그래서 **고정 추론 설정 = eta 1.0 · 20스텝 · 배치 1**로 확정했습니다.
3. **제출하지 않고도 서버 점수를 예측하는 환산식이 완성됐습니다(exp10).** `pred_total = 0.4×A_kit + 0.909×DV_w + 0.0734` — Action은 채점킷이 로컬에서 정확히 계산해 주고(A_kit), DINO·Video는 홀드아웃 점수(DV_w)가 서버 점수와 거의 직선 관계라, 두 제출 점수(0.302949 / 0.5167429)를 양 끝점 삼아 계수를 고정했습니다(검증오차 0.00003). 이제 모든 실험을 제출 없이 이 값으로 비교하니, 하루 3회 제한이 사실상 풀렸습니다.
4. **행동-영상 정렬은 shifted로 확정.** 조건 프레임(첫 장) 다음에 행동 a₀..a₁₄가 프레임 1~15를 만드는 배치입니다. 249개 에피소드로 다시 재보니 "이번 명령은 이번보다 다음 프레임 자세에 더 가깝다"가 모든 관절에서 성립했습니다.
5. **CFG(조건을 강하게 밀어붙이는 장치) 봉인.** 벤더 코드의 CFG 경로가 막혀 있어(켜면 텐서 모양이 깨짐) guidance_scale은 1.0으로 고정하고, CFG를 쓰는 실험은 후보에서 뺐습니다.

## 문제를 한 줄로
결국 "지금 화면 + 앞으로의 행동 → 미래 화면들"을 예측하는 일입니다. 그런데 팔 움직임은 사실상 명령이 정합니다(이번 명령 ≈ 다음 순간 자세, 상관 0.99+). 그래서 **모델의 진짜 숙제는 "명령을 화면(픽셀)으로 그려내고, 물체가 어떻게 반응하는지까지 표현"**하는 것입니다. 출력 16프레임의 첫 장은 받은 사진 그대로(공짜 정답)라 실제로 지어내는 건 15프레임이고, 평가 216문제는 전부 학습에 없던 장면이라(E2.5에서 겹침 0건 확인) 장면을 외우는 전략은 무효 — **일반화가 승부처**입니다.

## 큰 그림: 8단계 S0~S7 (시스템 부품 목록)
- **S0 채점 재현**(완료): 채점킷을 건드리지 않고 그대로 불러와 로컬 리더보드를 만들었습니다. 정답 영상으로 자가시험(GT self-test) 통과, 킷과 우리 채점기의 차이가 0.0000024로 사실상 동일.
- **S1 데이터**: 위 shifted 방식으로 자르고, 행동값은 통계로 z-정규화(평균 0·표준편차 1로 맞추기)합니다. 데이터셋 크기 편차는 제곱근으로 눌러 고르게 뽑고, **좌우 뒤집기·색조 변경은 금지**(행동과 화면의 대응이 깨짐), 약한 밝기/대비 정도만 허용.
- **S2 모델**: 주력은 **IRASim 파인튜닝**, Wan2.2는 조건부 서브, 베이스라인 확장(Track A)은 보험. 텍스트 조건은 뺐습니다.
- **S3 1차 학습(E3)**: 우선 우리 데이터의 화풍에만 적응시키는 단계입니다(점수는 아직 안 건드리고 순수 디노이징 학습만). 저장할 모델은 학습 손실이 아니라 **환산식 pred_total**로 고릅니다. 학습을 빠르게 하려고 영상 압축본(latent)을 미리 캐싱해 둡니다(10,357개, 19.8GB).
- **S4 2차 학습(E5→E6)**: 점수를 직접 파고드는 단계입니다. ① 채점킷과 똑같은 구조의 자체 IDM(영상→행동 역추정기)을 만들고 → ② 그걸로 "행동이 잘 복원되게" 순환 손실을 걸고 → ③ 세 항목 채점식을 미분 가능하게 복제해 점수를 직접 낮추는 학습(DRaFT-k)을 합니다. 모델이 무너지지 않게 안전장치(EMA/KL, 화질 하한)를 함께 겁니다. 강화학습(GRPO)은 예비.
- **S5 추론**: eta 1.0·20스텝·배치 1로, 320×512 원본 해상도로 뽑고 첫 프레임은 받은 사진을 그대로 넣습니다. 여러 후보를 뽑아 제일 좋은 걸 고르는 best-of-N도 씁니다(Action은 킷 실측으로, DINO·Video는 근사치로 채점하고, 정지영상을 항상 안전 후보로 포함). 학습 없이 추론만으로 이득 보는 기법들(FreeAction 등)은 아직 검토 단계.
- **S6 운영**: 한 번에 변수 하나만 바꿔 비교하고, 개선폭이 로컬-서버 오차보다 작으면 노이즈로 취급해 버립니다. 최종 제출은 Public 최고점이 아니라 **로컬 홀드아웃(처음 보는 장면) 최고점**으로 고릅니다.
- **S7 재현성**: 상대경로·UTF-8을 지키고, 검증 서버가 최신 GPU(Blackwell)라 torch 2.7.1+cu128로 맞추며, 라이선스 목록과 "단일 GPU로 4일/1시간 안에 재현" 스크립트를 챙깁니다.

## 채점 시스템에서 확정된 것들
- **Action(40%)은 채점킷이 로컬에서 최종 점수까지 직접 계산해 줍니다.** 그래서 이 항목만은 제출 없이 216문제 전부(비공개 포함) 정확히 알 수 있고, best-of-N 후보도 이 실측값으로 고릅니다. (DINO·Video는 정답이 서버에만 있어 홀드아웃으로 근사)
- 규격 요약: mp4 정확히 16프레임, 공통 전처리는 320×512 레터박스(비율 유지하며 여백 채우기). DINO는 이미지 특징기(DINOv2 ViT-S/14)로 프레임별 384차원, Video는 R3D-18로 512차원, Action은 킷 전용 추출기(3D 합성곱 → 양방향 GRU → (16,6), 55MB, 변경 금지).
- **함정 하나(F-A/F-B)**: 채점킷의 Action 추출기가 우리 학습 장면을 잘 못 알아봅니다(OOD, 학습 분포 밖). 그 바람에 **로컬 홀드아웃의 Action 점수는 포화**돼서 정지영상과 움직이는 영상조차 구분하지 못합니다(둘 다 ≈1.30). 그래서 Action 개선은 오직 평가 216문제 킷 채점으로만 판단하고, 홀드아웃은 DINO·Video 신호로만 씁니다.
- **기준선 다시 잡기(F-C)**: 평가 킷 채점에서 정지영상(0.4301)이 베이스라인 생성물(0.5792)보다 오히려 낫습니다. Action이 절대 관절각이라 첫 프레임 자세만으로 상당 부분 설명되기 때문이죠. → **E4가 이겨야 할 진짜 기준선은 "정지영상"**입니다.
