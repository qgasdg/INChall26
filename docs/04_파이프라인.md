## 목표·제약
Score = 0.3×DINO(cos) + 0.3×Video(cos) + 0.4×Action(MAE) 최소화.
학습 ≤4일 · 추론 ≤1h (RTX PRO 6000 96GB 1장), 외부 데이터·eval 학습 금지, 킷 변경 금지, 3회/일 제출.

## 문제 정식화 (수학적으로 다시 쓰기)
POMDP(부분관측 마르코프 결정과정: 현재 화면과 행동으로 다음 화면을 예측하는 틀) 관점에서, 학습 대상은 `p(o_{t+1:t+16} | o_t, a_{t:t+15})` — "지금 화면 o_t와 앞으로의 행동 a가 주어졌을 때 미래 화면들의 확률". action[t]≈state[t+1](이번 명령이 곧 다음 자세)이라 팔 포즈는 명령이 결정 → 실질 과제는 "명령→픽셀로 그려내기 + 물체 반응 표현".

## 8단계 구조 (작전 순서 S0~S7)
S0 킷 해부·로컬 리더보드 → S1 데이터 → S2 아키텍처(모델 구조) → S3 학습1단계 → S4 학습2단계(Action 특화) → S5 추론(영상 생성) → S6 실험 운영·제출 → S7 재현성·코드 제출

## v1.2 핵심 확정 사항 (submission_kit 전수 분석 = exp02)
- ★ **Action 점수는 채점 킷이 로컬에서 최종 MAE 값을 계산해 CSV에 적어준다** → 제출 전 216샘플 전부(Private 포함) **정확히 미리 계산 가능**. best-of-N(여러 번 만들어 최선 고르기)도 Action은 실측 기반으로 고름. 반면 DINO/Video는 정답(GT) 특징이 서버에만 있어 → 학습 홀드아웃으로 대략 근사(프록시).
- 확정 규격: mp4 **정확히 16프레임**(fps 무관) · 공통 전처리 = **320×512로 비율 유지하며 여백 채우기(zero-pad letterbox)** · DINO = 이미지 특징 추출기 `vit_small_patch14_dinov2.lvd142m`를 518×518로 (특징 16,384개) · Video = 영상 특징기 R3D-18에 (16,112,112) 비율 무시 늘리기(squish)로 (512개) · Action = 320×512, 값 범위 [-1,1] 입력.
- Action 채점기(extractor) 구조: **Conv3D(시간 방향 3D 합성곱, 시간 압축 없음) → Bi-GRU(시간 흐름 읽는 신경망, 256) → (16,6)**. 우리 복제본(surrogate IDM)은 같은 구조로 재학습해 원본과의 차이(전이 갭)를 최소화.
- **생성 해상도는 320×512 원본(native) 기본** (어차피 킷이 320×512로 바꾸므로 — 왕복 변환 손실 제거), 640×480과 비교실험(ablation).
- 킷 전처리 과정(letterbox→518/112/채점기)은 전부 크기 조정·여백 채우기라 → **미분 가능하게 복제 가능**(E6에서 점수를 직접 낮추는 학습 손실로 씀).
- 스케일 참고: 예시 제출(sample_submission)의 Action 평균 0.579 (0.088~1.148) vs 코사인은 보통 0.0x~0.5 → **Action이 가중치·값 크기 양쪽에서 총점을 지배할 가능성**.

## 파인튜닝(맞춤 재학습) 판단 (확정)
**주력 = Wan2.2-TI2V-5B (50억 파라미터 영상생성 모델, Apache-2.0 라이선스)에 LoRA(전체 대신 작은 부품만 얹어 값싸게 적응, r=64~128) + frame-level adaLN 행동 주입 모듈(zero-init, 0에서 시작해 안정 학습)**
근거: ① DINO 30%는 미공개 장면의 겉모습을 미리 알아야(prior) 잘 나옴 ② 4일이면 50억 모델 LoRA엔 충분, 처음부터(스크래치) 학습엔 부족 ③ Apache-2.0 + 사진→영상(TI2V)을 원래 지원 ④ Wan2.2-VAE의 압축 표현(latent)이 작아 가벼움.
대안 순위: Wan2.1-1.3B > CogVideoX-2B > LTX/SVD(라이선스 애매) > Cosmos(위험). Track A(베이스라인을 2~4억으로 키우기) = 보험·실험용 플랫폼.
사전학습 백본(뼈대 모델) 규정 위험 해소: **주최 스스로 DynamiCrafter_512 백본을 HF에서 받아 씀** → 우리도 써도 된다는 선례 확보.

## S1~S7 요약
- **S1(데이터)**: 학습 구간 `[t..t+15]↔[t..t+15]` 같은 인덱스로 자름(조건 프레임 포함 16장 출력, exp03 확정). 행동값 z-정규화. 데이터셋 크기 편차를 sqrt로 눌러 고르게 뽑는 샘플러. **좌우 뒤집기 금지(행동-기하가 안 맞음)·색조(hue) 변경 금지**, 약한 밝기/대비만. 4칸씩 건너뛰며 자르면(stride 4) 약 25만 구간.
- **S2(구조)**: Wan2.2-TI2V-5B에 LoRA + adaLN(zero-init) 주력, Track A는 보험, 텍스트 조건은 제거.
- **S3(학습1, ~2일)**: 흐름 맞춤 손실(L_FM)로 도메인 적응. 저장 모델(ckpt) 선택 기준 = 로컬 리더보드 점수 (학습 손실 아님).
- **S4(학습2, ~1.5일)**: 자체 IDM(킷과 같은 구조, 픽셀+압축표현) → 순환 손실 `‖IDM_lat(ẑ₀)−a‖₁` → 전체 채점식 직접 학습(DRaFT-k + EMA/KL로 원본에서 안 벗어나게 잡기). GRPO는 예비.
- **S5(추론)**: 결정론(η=0), 320×512 원본 16프레임, h264 저압축(품질값 CRF 낮게=고품질), best-of-N(Action 실측 기준), CSV는 킷으로만 생성.
- **S6(운영)**: 실험별 로그·한 번에 변수 하나만 바꾸는 비교·제출 아끼기·최종 파일 = **로컬의 처음 보는 검증셋 최고점** 수동 선택.
- **S7(재현성)**: 상대경로·UTF-8·환경 버전 고정(torch 2.7.1, lightning 1.9.3, timm — 킷 요구사항과 일치)·라이선스 목록·4일/1시간 재현 스크립트 (8/21 14:00 마감).

- (a) 익숙한 장면(in-domain): 각 데이터셋 에피소드의 5%를 떼둠

## exp03 — 대회 사이트 + baseline 코드 전수 분석
### 조건 프레임 확정 (3중 근거)
**제출 영상 = [조건 프레임(t=0, 받은 시작 사진) 포함 16프레임] = 실제로 지어내는 미래는 15프레임.**
① 학습 코드: `LeRobotSO100Dataset.__getitem__` — 프레임[t..t+15] ↔ 행동[t..t+15] 같은 인덱스 ② 추론: DDIM 인페인팅(가려진 부분 채우기, mask=cond_mask)으로 0번 프레임 고정 ③ 킷 `build_inference_batch` — buffer[0]=조건 이미지.
→ 0번 프레임은 "공짜 정답" — 우리 모델도 출력 0번에 조건 프레임을 넣어야 정답(GT)과 자리가 맞는다.

### 베이스라인 실체
- DynamiCrafter LatentVisualDiffusion(압축표현 영상 디퓨전), **핵심 신경망(UNet) 1,100만 파라미터** (채널 32), 시간 방향 conv+attn, 프레임 16장.
- 백본: HF `Doubiiu/DynamiCrafter_512` — 압축부품(VAE)·이미지의미요약(CLIP)만 불러오고, **UNet은 처음부터(스크래치) 학습**.
- v-prediction(잡음 대신 속도를 예측하는 방식) + zero-SNR rescale, 프레임별 인코딩, 입력 채널 8개(영상 압축표현 4 + 조건 압축표현 4 이어붙임) + CLIP 이미지 cross-attn + 행동 조건(6차원), 텍스트는 빈 캡션.
- 해상도 320×512 (압축표현 40×64), 학습 배치1×누적2, 학습률 1e-4, 10만 스텝/48시간, 검증 5% (seed 0).
- **추론: DDIM 50스텝, CFG=1.0(사실상 미사용), η=1.0(매번 조금 다름!), 한 번에 1개, seed 0** → E1에서 개선 여지 있음이 확정.
- 카메라 자동선택 = 손목/집게/팔 시점 제외. eval 설정에 `camera_key: observation.images.top` 흔적 → **eval 정답이 위에서 내려다본(top-view) 계열이라는 힌트**.
- 베이스라인의 metrics.py(MSE/PSNR/SSIM/LPIPS/FVD/FID 같은 일반 화질 지표)는 리더보드 채점식과 무관 — 로컬 리더보드는 exp02 규격으로 따로 만든다.
