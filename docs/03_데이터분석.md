# 데이터 분석 리포트 v2 (노션 요약)

> 출처: 팀 노션 [데이터 분석](https://app.notion.com/p/39f6af58538080ec9b58ea0377c81bbc) (작성 2026-07-16 / 2026-07-18 수집)

## 1. 결론 요약
- **태스크(과제)**: 현재 사진 1장(640×480 PNG) + 앞으로 할 16스텝 행동표(16×6 npy) → **16프레임(초당 6장) 영상 생성**. 평가 샘플 **216개** (Public 30% / Private 70%).
  - ※ exp03에서 확정: 출력 16프레임은 **조건 프레임(t=0, 받은 시작 사진) 포함**, 실제로 지어내는 미래는 15프레임 ([04_파이프라인.md](04_파이프라인.md) 참고).
- **train(학습 데이터)은 100% 공개 데이터**: 허깅페이스(HF, AI 모델·데이터 공유 사이트)의 로봇 데이터 형식(LeRobot) **SO-100 로봇 커뮤니티 데이터셋 128묶음**을 초당 6장으로 솎아낸 것. 최소 101개(79%)가 SmolVLA(로봇 행동 예측용 공개 모델, 논문 2506.01844)의 학습 목록과 겹친다. 단 **외부 데이터 금지 → 원본 HF(초당 30장·여러 카메라 시점) 추가 사용 불가**. 허용 라이선스로 공개된 사전학습 모델은 사용 가능.
- **action[t] ≈ state[t+1]** — 이번 스텝 행동 명령이 곧 다음 순간 팔의 실제 자세와 거의 같다 (평균 오차 1.65°, 상관 corr 0.99+): action은 사람이 조종하는 팔(리더암)의 목표각이라, 팔 포즈는 명령이 거의 결정한다. 그래서 모델의 실질 과제 = "명령을 픽셀(화면)로 그려내기 + 물체 반응까지 표현".
- eval 사진 4장을 표본 점검(스팟체크)하니 train 장면과 안 맞음 → **평가엔 미공개 장면이 섞인 것으로 추정** → 장면을 외우는 것보다 처음 보는 입력에도 통하는 일반화가 필요.

## 2. 데이터 구성
```
open (1)/
├── data/
│   ├── train/                      # 128개 LeRobot 데이터셋 (<user>/<dataset>)
│   │   ├── .../data/chunk-000/episode_XXXXXX.parquet
│   │   ├── .../meta/info.json, episodes.jsonl
│   │   ├── .../videos/chunk-000/<camera_key>/episode_XXXXXX.mp4
│   │   └── so100_action_statistics.json   # action 정규화 mean/std
│   └── eval/
│       ├── images/sample_000000~000215.png   # 시작 프레임 640×480
│       └── actions/sample_000000~000215.npy  # (16,6) float32, deg
├── baseline/        # DynamiCrafter 기반 action-conditioned latent video diffusion (11M UNet)
└── submission_kit/  # mp4 → feature CSV (평가 추출기 포함, 변경 금지)
```

### 규모 (128개 meta 전수 집계)
| 항목 | 값 |
|---|---|
| 데이터셋 | 128 (HF repo ID 그대로) |
| 에피소드 / 프레임 | 11,132 / 1,025,666 (6fps) |
| 로봇 | SO-100 계열 6DoF (so100 125, blue 2, red 1) |

| 해상도 | 480×640 123개, 1080×1920 3개, 720×1280 2개 |
| 카메라 | 데이터셋당 1개 키만 유지 |
| 에피소드 길이 | 17~1,072프레임 (중앙값 ~104 ≈ 17초) |

## 3. Feature 상세 (parquet 행 = 프레임)
| feature | 형식 | 의미 |
|---|---|---|
| action | float32 (6,) | 리더암 목표 관절각[deg]: shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper |
| observation.state | float32 (6,) | 팔로워암 실측 관절각 |
| observation.images.image | 480×640×3 | h264 mp4 프레임 |
| timestamp | float32 | 1/6s 간격 |

- episodes.jsonl: 에피소드(로봇이 한 작업을 처음부터 끝까지 한 번 수행한 기록)별 자연어 작업 설명 (집어서 옮기기 위주, 일부 부실).
- so100_action_statistics.json: 개수 ≈ 전체의 95% (검증용 5% 제외한 통계로 추정). **eval의 행동값은 정규화 안 된 도(deg) 단위 → 이 통계로 z-정규화(평균 0·표준편차 1로 맞추기) 필요**.

## 4. Feature(항목) 간 관계 (30개 데이터셋 표본, 4,408프레임)
- **action(명령) ↔ state(실제 자세)**: 상관 0.993~0.999 (집게 gripper는 0.939). `|이번 명령 − 다음 실제자세|=1.65° < |이번 명령 − 이번 실제자세|=2.25°` → 이번 스텝 명령은 사실상 다음 순간 자세의 예측치.
- 관절끼리 맞물림(커플링): 어깨상하(shoulder_lift)↔팔꿈치(elbow_flex) +0.89 → 실제로 독립적으로 움직이는 자유도는 6개보다 적다. 어깨 좌우(shoulder_pan)만 독립.
- **집게(gripper)의 특수성**: 물체를 쥘 때 목표각과 실제각이 벌어짐 → 명령-자세 차이(잔차)가 "쥐는 순간" 신호가 된다. Action MAE에서 집게 차원은 따로 지켜볼 가치.
- 차원별 표준편차(std)가 14~62로 스케일 차이 큼 → 정규화 필수. 손목회전(wrist_roll)은 데이터셋마다 값이 제각각(이질성 큼).

## 5. 평가 산식의 실체 (submission_kit 결합)
| 성분 | 가중치 | feature | 거리 |
|---|---|---|---|
| DINO | 0.3 | **DINOv2 ViT-S/14** CLS, 프레임별 16×384 | GT와 cosine distance |
| Video | 0.3 | **R3D-18**(Kinetics) 512-d 클립 feature | GT와 cosine distance |
| Action | 0.4 | 고정 action extractor 역추정 action | GT(정규화)와 MAE |

핵심 통찰:
- **영상 무리의 사실감(분포 거리, FVD)이 아니라 문제 하나하나마다 정답과의 매칭** → "그럴듯한 영상"이 아니라 "그 문제의 정답(GT)과 닮은 영상"이 목표. 그래서 다양하게 만드는 건 오히려 위험(시드 고정·결정론 생성·guidance 튜닝으로 흔들림을 줄인다).
- Action 40% + 채점기(extractor) 고정 → **채점기가 알아보기 쉽게 팔 움직임을 선명하게 그려내는 것**이 점수 40%를 좌우.
- eval의 정답(GT) 영상은 서버에만 있음 → **학습 데이터 일부를 떼어(홀드아웃) 로컬 리더보드로 채점을 재현**하는 게 필수.
- Public은 약 65샘플이라 노이즈가 큼 + 하루 10회 제한 → Public 순위에 과하게 맞추지 말고 로컬 지표를 믿을 것.

## 6. 규정 제약 (전략 직결)
- 외부 데이터 금지 (HF 원본 30fps·여러 시점 활용 불가), eval을 학습에 쓰는 것 금지 (모델로 정답을 만들어 다시 학습하는 pseudo-labeling(가짜 정답 학습)도 포함).
- 사전학습 모델: 공개 가중치 + 허용 라이선스 (MIT/Apache 2.0/CC BY/CC BY-NC 등 자유 사용 허가).
- 컴퓨트(연산 자원): 학습 ≤4일, 추론(영상 뽑기) ≤1시간 (RTX PRO 6000 96GB 1장) → 216샘플 × 16프레임 = **샘플당 평균 ~16.6초** 안에 끝내야 함.
- 제출킷 변경 금지, 만든 CSV를 나중에 손보는 후처리 금지.

## 7. 전략 우선순위
1. [최우선] Action fidelity (0.4): 조건 주입 방식 비교 + 로컬 자가 채점 루프.
2. [평가 재현] train 홀드아웃 로컬 리더보드 (0.3/0.3/0.4 그대로).
3. [샘플별 매칭] 결정론적·저분산 생성 세팅 튜닝.
4. [도메인 갭] 데이터셋 균형 샘플링, 색/조명 증강 (외부 데이터 없이).
5. [품질 필터링] SmolVLA식 큐레이션으로 저품질 데이터셋 제외 실험.
6. [컴퓨트 예산] 스텝 수·해상도 트레이드오프 사전 계산.

## 8. 한계 (이 분석이 못 본 부분)
- 상관 분석은 128묶음 중 30개의 첫 에피소드만 표본으로 봄. eval-train 대조는 8개 표본 점검. SmolVLA 겹침 101/128은 최소치(더 많을 수 있음).
- 서버가 코사인 점수를 어떻게 합치는지(프레임별로 평균 vs 통째로 펼쳐서 계산) 공개 안 됨 → 로컬에서 두 방식 다 계산해 병행.
